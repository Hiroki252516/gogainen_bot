# 11. Seed Questions

## 基本方針

事前テストは、正答を文章表現だけで推測しにくくした修正版5問を `pretest_v2` として採用する。被験者には選択肢のみを提示し、理由欄と自信度欄は出さない。

各選択式問題には以下を持たせる。

- correct option
- M1 option
- M2 option
- M3 option
- unknown option

問題作成時は次を守る。

- 誤答は、関連する別概念・工程としては自然だが、問われた概念には当てはまらない内容にする
- 正答と誤答の文体、長さ、専門性を可能な限り揃える
- 「必ず」「単に」「〜だけ」「名前に〜とあるため」などの正解推測手掛かりを避ける
- M1〜M3と診断意図は内部メタデータとして保存し、被験者には表示しない
- 表示順は参加者ごとにランダム化し、実際の表示順を保存する

旧 `pretest_v1` は既存回答との参照整合性のため削除せず、非active化する。

添付問題の `L4` は旧設計の最強支援表記として記録するが、現行の3段階学習ではL3/L2/L1を使わない。システム、DB、AI schemaには `L4` を追加しない。

再テストは正式問題を `retest_v1` としてseedする。L0確認、転移テストは現行参加者フローから外すため、`l0_temporary_v1`, `transfer_temporary_v1` はseedしないか、既存DBに残る場合は非active化する。

## PRE_Q01 Transformer

Transformerの計算構造を最も適切に説明しているものはどれか。

A. Attentionで入力内の関係を集約し、FFNで各位置の表現を変換する処理を層状に組み合わせた構造。
B. 入力された文章を一つの固定長ベクトルに圧縮し、そのベクトルを知識として保存・検索するための表現形式。
C. 入力列を先頭から順に処理し、直前までの隠れ状態を次の位置へ受け渡すことで文脈を表す構造。
D. 入力列の各要素を対応する出力要素へ順番に置き換え、主に文章を別の文章へ変換するための構造。
E. わからない。

Labels: A correct / B M1 / C M2 / D M3 / E unknown

診断意図:

- M1: モデル構造を固定長表現・保存形式として捉えている
- M2: TransformerとRNNの処理構造を混同している
- M3: `transform` や翻訳用途から構造を判断している

## PRE_Q02 Attention

Transformer層におけるAttentionの処理を最も適切に説明しているものはどれか。

A. 各トークンと他のトークンの関連度を計算し、その重みで情報を集約して文脈に応じた表現を作る処理。
B. 学習時に誤差の大きい入力箇所を選び、その箇所へより多くのパラメータ更新を割り当てる制御機構。
C. 各トークンの表現を同じ変換関数に通し、位置ごとに特徴を更新して次の層へ渡す処理。
D. 各単語に文全体で一つの重要度を付け、重要度の高い単語を抽出して文の要点を表す処理。
E. わからない。

Labels: A correct / B M1 / C M2 / D M3 / E unknown

診断意図:

- M1: Attentionを学習・最適化の制御機構として捉えている
- M2: AttentionとFFNの役割を混同している
- M3: トークン間関係ではなく、単語の重要度ランキングとして捉えている

## PRE_Q03 LLMの学習段階

本研究で扱うLLMの学習過程の説明として、最も適切なものはどれか。

A. 大規模データで基盤能力を獲得し、指示応答の訓練を行い、その後に人間の選好や安全性に合わせて調整する。
B. 入力をトークン化し、Attentionで文脈表現を作り、出力確率から次のトークンを選ぶ一連の計算段階。
C. 大規模データで学習し、RAGで外部知識を追加し、プロンプトで回答形式を調整する三段階。
D. 学習前に初期性能を測定し、訓練データで学習を行い、学習後に同じ指標で性能を再評価する三段階。
E. わからない。

Labels: A correct / B M1 / C M2 / D M3 / E unknown

診断意図:

- M1: 学習段階と推論時の内部処理を混同している
- M2: モデル学習とRAG・プロンプトなどの利用時技術を混同している
- M3: 「事前・事後」を評価タイミングとして解釈している

## PRE_Q04 事前学習

LLMの事前学習を最も適切に説明しているものはどれか。

A. 大規模で多様なデータを用い、次トークン予測などを通じて言語パターンや一般的知識の基盤を獲得する。
B. モデルの利用開始前に、入力形式、禁止事項、回答方針をシステムプロンプトとして設定する準備工程。
C. 指示と望ましい回答の組を教師ありデータとして学習し、指示に沿う応答能力を獲得する工程。
D. 本格的な学習の前に小規模データで予備訓練を行い、学習率やバッチサイズなどの条件を決める工程。
E. わからない。

Labels: A correct / B M1 / C M2 / D M3 / E unknown

診断意図:

- M1: パラメータ学習と利用時設定を混同している
- M2: 事前学習とインストラクションチューニングを混同している
- M3: 「事前」を小規模な予備実験という意味で解釈している

## PRE_Q05 事後学習

LLMの事後学習を最も適切に説明しているものはどれか。

A. 事前学習済みモデルを、人間の選好や評価を用いて、安全性・有用性・望ましい応答傾向に合わせて調整する。
B. 運用開始後の会話ログを監視し、問題のある回答を記録・修正してサービス品質を保つ保守工程。
C. 追加の大規模テキストで次トークン予測を続け、モデルの一般知識と言語生成能力をさらに広げる。
D. モデルが回答を生成した後、その回答を別の処理で検査・修正してから利用者に提示する後処理工程。
E. わからない。

Labels: A correct / B M1 / C M2 / D M3 / E unknown

診断意図:

- M1: モデル学習と運用・保守を混同している
- M2: 事後学習と継続的な事前学習を混同している
- M3: 「事後」を推論後の後処理として解釈している

## 導入前の内容妥当性確認

- AI・機械学習の専門家2名以上が、正答とM分類の妥当性を独立確認する
- 対象者に近い5〜10名で認知インタビューを行い、文章の長さや表現だけで選んでいないか確認する
- 知識がない参加者でも特定の選択肢へ偏る場合は、表現上の手掛かりを再点検する
- 誤答選択肢がほとんど選ばれない場合は、診断用選択肢として再作成する

## Formal Retest

再テストは事前テストと同じ5構成概念を別文面の選択式で測る。被験者には理由欄と自信度欄を出さない。

現行 `retest_v1` には旧事前テストと同種の正解推測手掛かりが残るため、本実験前に同じ基準で別途改訂・妥当性確認する。

## L0 / Transfer

現行参加者フローではL0確認と転移テストを実施しない。旧DBや旧seedで `l0_temporary_v1`, `transfer_temporary_v1` が存在する場合は、出題対象にしない。

## RAG Reference

学習セッションでは `rag_ready_教材` をローカルRAGとして参照する。

- `chunks.jsonl`
- `vectors_tfidf_sparse.npz`
- `tfidf_vectorizer.joblib`

取得した上位3チャンクをAI payloadの `rag_context` に入れる。統制群にも同じ教材コンテキストを渡すが、統制群では誤概念タイプや過去ログに基づく個別化は行わない。
