# 03. Misconception Taxonomy

本システムでは、最終分類としてM1〜M4を採用する。過去案にあった「日常語混同」「因果誤認」「定義暗記型」「適用条件誤解型」「表層キーワード依存型」などは、最終的には以下の4分類へ統合する。

## 分類の使い方

- M1〜M4は内部分析ラベルである
- 被験者画面にMラベルを直接表示しない
- 管理画面、CSV、AIログには保存する
- 統制群でも分析用に分類してよいが、教授方略には使わない
- M4は再テストやL0確認の記述内容から、文脈適用の失敗が明確な場合に内部判定する

## M1: カテゴリー誤分類型

### 定義

対象概念が何の種類のものかを取り違えている状態。

### 例

- Embedding = データの保存場所
- Attention = 人間の注意や集中
- Loss = AIが失敗して自信を失う状態
- Prompt = AIの内部にある考える力
- RAG = AIの中に巨大な図書館が物理的に入っている状態

### 診断基準

学習者の回答が、概念を以下のような本来とは異なるカテゴリーに置いている。

- 物理的な場所
- 人間の心理状態
- AIの人格・気分
- 単なる保存
- 単なる知識そのもの
- 社会的な正しさや常識

### 教授方略

カテゴリー再定位型説明。

- 「何ではないか」を明確にする
- 「何の種類の概念か」を言い直す
- 誤カテゴリーと正カテゴリーを比較する
- 正しい上位カテゴリーを先に置いてから具体例に進む

## M2: 類似概念境界混同型

### 定義

似ている概念の違いが分かっていない状態。

### 例

- Attention と Embedding の混同
- Token と Embedding の混同
- 過学習 と 汎化 の混同
- Fine-tuning と Prompt engineering の混同
- RAG と Fine-tuning の混同
- Loss と Accuracy の混同
- 正則化 と 正規化 の混同

### 診断基準

学習者が関連する別概念の説明をしている。または2概念を「同じもの」と扱っている。

判定の典型:

- Aを説明すべき問題でBの定義を書いている
- 「どちらも同じ」「似たもの」として境界を説明できない
- 入力、処理、出力、更新対象の違いを取り違えている

### 教授方略

境界比較型説明。

- 2概念の比較表
- 役割の違い
- 入力、処理、出力の違い
- 使う場面の違い
- 「この場合はどちらか」を判断する短問

## M3: 表層特徴・キーワード反応型

### 定義

問題文の目立つ単語、数値、記号、漢字、英単語の直訳などに反応し、原理や構造に基づかずに答えている状態。

### 例

- 「訓練」と書いてあるから過学習
- Attention = 重要な単語を探す処理
- Loss = お金やデータが失われる量
- Fine = きれいにするという意味だから文章を整える
- 正則化 = 「正」という字があるから出力を正しくする
- Prompt = 質問文と書いてある場合だけ該当する

### 診断基準

回答理由が、概念の仕組みではなく、表面的な語感・単語・漢字・英単語の直訳に依存している。

判定の典型:

- 理由が「この単語があるから」だけで終わる
- 指標や文脈の関係を説明していない
- 正答選択肢に近い語を選んだだけで理由が不十分

### 教授方略

深層構造注目型説明。

- キーワードではなく判断基準を示す
- 表層的判断がなぜ危険かを示す
- 原理、構造、関係性を説明させる
- 似た表層語を含む反例を出す

## M4: 文脈転移失敗型

### 定義

特定の文脈では説明できるが、文脈が変わると概念を適用できない状態。

### 例

- 画像分類では過学習が分かるが、チャットボットの言い換え質問では分からない
- Promptを質問文としては分かるが、命令文や制約文を含む入力では判断できない
- RAGを検索付きQAでは分かるが、社内文書参照の業務支援では説明できない
- Attentionを文章処理では説明できるが、画像説明モデルの領域重み付けに適用できない

### 診断基準

基本問題・同型問題では正答しているが、転移問題で誤答する。あるいは学習時と異なる文脈で、同じ判断基準を使えない。

M4は独立した転移テストでは扱わない。再テストやL0確認の記述内容から文脈適用の失敗が明確な場合に内部判定する。

### 教授方略

文脈変換型練習。

- 学習時の文脈と転移先の文脈を比較する
- 共通構造を抽出する
- 別文脈で同じ概念を使わせる
- 「表面は違うが同じ判断基準」を言語化させる

## Unknown: 知識不足

「わからない」選択肢、または記述式テストで概念に関係する記述がほぼない場合。誤概念ではなく、基礎知識不足として扱う。事前テストでは理由記述を収集しないため、選択肢だけで判定する。

Unknownは同種誤答再発率の分子・分母には含めない。ただし、知識不足の継続として別集計できるように保存する。

## Ambiguous: 判定不能

記述式テストで選択肢と理由記述が矛盾する、またはAI診断の信頼度が低い場合。管理画面で要確認として表示する。事前テストでは理由記述を収集しない。

例:

- 正答選択肢を選んだが理由が明らかにM2
- 誤答選択肢を選んだが理由は正しい
- 複数の誤概念が同程度に含まれる

Ambiguousは自動評価から除外するのではなく、`diagnosis_confidence` と `requires_manual_review` を保存する。

## 旧分類から最終分類への対応

5月18日案ではM1〜M6の分類が使われていた。5月25日案では先行研究との対応を整理し、現在のM1〜M4へ統合する。

| 旧分類 | 最終分類 | 理由 |
|---|---|---|
| 日常語混同型 | M1 カテゴリー誤分類型 または M3 表層特徴型 | 日常語の意味へ置き換える場合はM1、単語の表面だけで判断する場合はM3 |
| 類似概念混同型 | M2 類似概念境界混同型 | 近接概念の境界が曖昧なため |
| 因果誤認型 | M2 または M3 | 別概念との関係誤りならM2、表層的な因果語への反応ならM3 |
| 定義暗記型 | M4 文脈転移失敗型 | 定義は言えるが事例へ適用できないため |
| 適用条件誤解型 | M4 文脈転移失敗型 | 文脈や条件が変わると使えないため |
| 表層キーワード依存型 | M3 表層特徴・キーワード反応型 | 表面特徴に基づく判断のため |

## 診断優先順位

1. 「わからない」または空欄なら `unknown`
2. 選択肢に内部ラベルがある場合は初期ラベルとして採用
3. 事前テストでは理由記述を使わず、選択肢ラベルだけで診断する
4. 再テスト、L0確認では理由記述が初期ラベルと矛盾する場合にAI診断で上書き候補を出す
5. 再テストやL0確認で文脈適用の失敗が明確な場合はM4
6. 信頼度が低い場合は `ambiguous` として手動確認対象

## 用語別の代表誤概念

| 用語 | M1 | M2 | M3 | M4 |
|---|---|---|---|---|
| Attention | 人間の注意 | Embeddingと同じ | 重要語を探すだけ | 画像領域や音声文脈に適用できない |
| Embedding | 知識の保存場所 | AttentionやTokenと同じ | 埋め込みという語感だけで判断 | 文・画像・ユーザーなど異なる対象の表現に適用できない |
| Token | 意味そのもの | Embeddingと同じ | 短い記号だけ | 日本語分割やサブワード文脈で説明できない |
| 過学習 | 勉強しすぎて疲れる | 汎化と同じ | 訓練という語だけで判断 | チャットボットや推薦など別文脈で説明できない |
| 汎化 | 一般常識を理解 | 過学習と同じ | 細部を無視する | 未知質問や新規データ文脈で説明できない |
| Fine-tuning | AIの性格調整 | Prompt engineeringと同じ | fineの語感で判断 | ドメイン適応や分類器調整へ適用できない |
| Prompt | AI内部の思考力 | 学習データやFine-tuningと同じ | 質問文だけ | 命令、制約、例示を含む入力に適用できない |
| RAG | AI内の物理的図書館 | Fine-tuningと同じ | 検索結果コピー | 社内文書、FAQ、法務文書などへ適用できない |
