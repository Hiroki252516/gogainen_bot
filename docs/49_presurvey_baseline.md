# 事前アンケート

## 事前アンケートの現行契約（仕様版63更新）

新規参加者は仕様版63 / `experiment-plan-2026-11-23-presurvey-weekly-frequency-understanding-anchor-v1`で同意後・事前テスト前に回答する。新規参加者は`four_topic_fundamentals`に固定し、`presurvey-four-topic-baseline-v12`を使う。AI利用頻度は「普段の生活では、1週間あたり何日程度AIを利用しますか。」と尋ね、「0日」〜「7日」の8択から回答し、`general_ratings.ai_usage_days_per_week`へ厳密な整数`0`〜`7`で保存する。理解度は経験項目で「ある」と回答した用語だけに表示し、中央を「どちらとも言えない」として`neither`で保存する。理解度質問は「{用語}の基本的な仕組みを、どの程度理解していますか。」とし、目安として「知らない」=1、「一部知っている」=2、「知っている」=4、「説明できる」=5を示す。事前経験質問の冒頭を「実験を始める前に、」、第三選択肢を「判断できない」と表示する（保存値`cannot_recall`は維持）。4用語版の下位用語は`instruction_tuning` / 「インストラクションチューニング」、`human_feedback_post_training` / 「事後学習」と表示する。AI自己評価3項目は1〜5の必須回答とし、具体例を各項目に表示する。「評価できない」は設けない。全数値評価は数字を上、選択文言を下に配置する。仕様版62以下の保存回答・snapshot・旧ラベルは変換しない。事後アンケートは[posttest-5point-v5](52_posttest_five_point_evaluation.md)。尺度の妥当性や研究上の承認はこの変更だけでは確認されない。

| 問題モード | アンケート版 | 対象用語 |
| --- | --- | --- |
| `application`（履歴復元用） | `presurvey-baseline-v5` | 事前学習、ファインチューニング、RAG、プロンプトエンジニアリング、マルチエージェント、記憶プロセス |
| `basic_understanding`（履歴復元用） | `presurvey-baseline-v5` | 事前学習、ファインチューニング、RAG、プロンプトエンジニアリング、マルチエージェント、記憶プロセス |
| `four_topic_fundamentals`（新規参加者） | `presurvey-four-topic-baseline-v12` | Transformer、事前学習、インストラクションチューニング、事後学習、マルチエージェント、記憶プロセス |

4用語版の事前アンケートは、問題モード名が示す4つの大項目ではなく、LLMの学習段階を下位用語（事前学習・インストラクションチューニング・事後学習）に分けて個別に尋ねる。用語の定義や正答に相当する説明は質問内に提示しない。

### 用語の経験・理解度

各用語について、まず「実験を始める前に、見たり聞いたりしたことがありますか」と尋ねる。経験項目は必須で、保存値は次のとおり。

| 表示 | 保存値 |
| --- | --- |
| ある | `experienced` |
| ない | `not_experienced` |
| 判断できない | `cannot_recall` |

「ある」の場合に限り、「{用語}の基本的な仕組みを、どの程度理解していますか。」を必須表示する。経験質問は「実験を始める前に、{用語}という用語を見たり聞いたりしたことがありますか。」とする。

| 表示 | 保存値 |
| --- | --- |
| 全く理解していない | `not_at_all` |
| あまり理解していない | `hardly` |
| どちらとも言えない | `neither` |
| ある程度理解している | `moderately` |
| よく理解している | `well` |

選択の参考として「回答の目安」を表示する。基本的な仕組みを知らない場合は1、一部知っている場合は2、知っている場合は4、説明できる場合は5を目安とする。3は中間の「どちらとも言えない」であり、目安の例は付けない。

「ない」「判断できない」の場合は理解度を表示せず、`prior_term_understanding`の該当値をJSON `null`として保存する。未提示を低い理解度へ置き換えない。APIも経験と理解度の組合せを検証し、経験が`experienced`なら理解度を必須、それ以外ならnullを要求する。

### 普段のAI利用

- 利用頻度（現行v12）: 「普段の生活では、1週間あたり何日程度AIを利用しますか。」と尋ねる。「0日」〜「7日」の8択を必須回答とし、`ai_usage_days_per_week`に整数`0`〜`7`で保存する。直近30日区分と`ai_usage_frequency_30d`はv11以前の履歴形式である。
- 行動別の自己評価: 共通説明「次の各項目について、最も当てはまるものを選んでください。」を表示し、次の3項目を個別に尋ねる。
  - 「AIに目的を伝え、目的に合った回答を得ることができますか。」例：週末の外食先を探すとき、希望を伝えて候補を提案してもらう。
  - 「AIの回答が期待と異なるとき、指示や条件を修正できますか。」例：候補が希望と違うとき、予算や移動時間などの条件を伝え直す。
  - 「AIの回答が正しいか、公式サイトや別の資料で確かめられますか。」例：AIが答えた営業時間を、お店の公式サイトで確認する。
- 各項目は「全くできない／あまりできない／どちらでもない／ある程度できる／よくできる」の1〜5から選ぶ。整数1〜5を`general_ratings.ai_proficiency`へ保存し、「評価できない」は受け付けない。利用頻度・自己評価は全項目必須とする。注意確認問題は設けない。

### API・保存・出力

GET `/api/participants/{id}/presurvey`は参加者の保存済み問題モードに基づき、`survey_version`と`term_items`（各用語の`key`・`label`）を返す。仕様版63の新規参加者にはv12を返す。POST同URLは6用語の経験・条件付き理解度、`general_ratings.ai_usage_days_per_week`（厳密な整数0〜7）、3項目のAI自己評価（整数1〜5）を検証する。直近30日区分の`ai_usage_frequency_30d`はv12では拒否する。事前アンケートが未完了なら事前テストを開始できず、保存成功後にpretestへ進む。回答は既存の`ParticipantSurvey`へ`phase=presurvey`・版付きJSONとして保存し、DB列は追加しない。同一内容の冪等再送は保存済み結果を返し、同じ冪等キーで異なる内容を送ると競合を拒否する。仕様版62以下の回答JSONは変換しない。

参加者ログ、アンケートCSV、全体ログCSVおよび対応するExcel出力では、`phase`・`survey_version`・回答JSONを保つ。事前回答は事後アンケートの回答として扱わず、事後評価や仮説指標の入力へ合算しない。

## 旧アンケートと履歴

- `presurvey-four-topic-baseline-v11`（仕様版62の2つのprotocol）: 同じ版名が異なるpayloadに使われた。`experiment-plan-2026-11-22-presurvey-understanding-anchor-guidance-v1`では理解度の回答目安を1・2・4・5に更新した一方、AI利用頻度は直近30日の区分（`ai_usage_frequency_30d`）を維持した。`experiment-plan-2026-11-22-presurvey-weekly-ai-usage-frequency-v1`では週あたり0〜7日の整数（`ai_usage_days_per_week`）に変更した一方、そのprotocolの理解度ガイドは旧形式だった。これらの仕様版62の記録は閲覧専用で、payloadを相互変換しない。現行仕様版63では両方の変更を統合したv12を使用する。

- `presurvey-four-topic-baseline-v7`（仕様版58）: 5段階理解度（中間値`slightly`）を使い、AI利用自己評価3項目の質問文を更新した。3つ目の例を削除し、「評価できない」を許容した。仕様版59では理解度3番の値と表示、自己評価の中央ラベルおよび選択肢を変更し、過去v7回答は読み取り専用で保全する。
- `presurvey-four-topic-baseline-v8`（仕様版59）: 理解度の中央値を`neither`とし、AI自己評価から「評価できない」を除いた。経験質問は「実験の説明を受ける前に」、理解度質問は「基本的な意味や働き」を尋ね、対象語を「人の評価・好みを用いる事後学習」と表示した。回答は仕様版61でも変換しない。
- `presurvey-four-topic-baseline-v9`（仕様版60）: 経験質問を「実験を始める前に」、第三選択肢を「判断できない」、理解度質問を「基本的な仕組み」に更新し、対象語を「事後学習」と表示した。自己評価例は最初の2項目だけで、理解度の目安と3項目目の例はなかった。回答キー・保存payload・尺度はv8から変更しなかった。
- `presurvey-four-topic-baseline-v10`（仕様版61）: 理解度設問に回答の目安を追加し、自己評価3項目すべてに例を表示する。3項目目の例はAIが答えた営業時間を公式サイトで確かめる内容。回答キー・保存payload・尺度はv9から変更しない。
- `presurvey-four-topic-baseline-v12`（仕様版63）: 週あたり0〜7日の整数回答と、理解度の回答目安（1・2・4・5）を統合した。AI利用頻度の質問文は「普段の生活では、1週間あたり何日程度AIを利用しますか。」、保存キーは`ai_usage_days_per_week`。v11を含む旧回答JSONは変更・相互変換しない。
- `presurvey-four-topic-baseline-v6`（仕様版57）: 5段階理解度を引き継ぎ、AI利用自己評価には従来の3項目見出しと3つの具体例を表示した。仕様版58では設問文を更新し、3つ目の例を削除した。仕様版57の回答は読み取り専用で保全する。

- `presurvey-four-topic-baseline-v5`（仕様版55）: AI活用自己評価の3項目に具体例を表示した。理解度は4段階（`not_at_all`／`slightly`／`moderately`／`well`）。仕様版56のv6では「ほとんど理解していない」／`hardly`を追加し、保存済みv5回答は変換しない。

- `presurvey-baseline-v3`（仕様版48・49）: 標準2モードで見聞き経験と条件付き理解度、普段のAI利用を取得した。理解度質問は「実験前の時点で、{用語}の基本的な意味や働きをどの程度理解していましたか。」だった。仕様版50では保存版v4に進め、新規参加者の表示文のみを更新する。
- `presurvey-four-topic-baseline-v3`（仕様版50）: 4用語版の対象6項目に`fine_tuning` / 「ファインチューニング」を使用した。仕様版51はキーを`instruction_tuning`、表示を「インストラクションチューニング」とするv4を使う。過去の値は変換しない。
- `presurvey-four-topic-baseline-v2`（仕様版48・49）: 4用語版の対象6項目に`instruction_tuning` / 「指示チューニング」を使用した。仕様版51の表示名・設問対象とは別版として保持する。

- `presurvey-baseline-v2`（仕様版37/38等）: 用語知識を「知らない／聞いたことがある／意味を知っている／説明できる」の4択で取得し、保存値は`unknown`、`heard_of`、`knows_meaning`、`can_explain`。一般AI利用は各1〜10評定だった。
- `presurvey-four-topic-baseline-v1`（仕様版44以降の旧4用語形式）: Transformer、LLMの学習段階、マルチエージェント、記憶プロセスの4項目を取得した。
- `presurvey-baseline-v1`（仕様版36）: 用語ごとに「知っていた／知らない」のBooleanを保存した。

これらの保存済み回答は新形式へ変換・補完しない。仕様版49では事後アンケート`posttest-5point-v1`でシステム評価2項目、教材評価6項目、任意自由記述を取得した。現行仕様版63の新規参加者は`posttest-5point-v5`を使用する。新規の事後評価は整数1〜5のみとし、過去の評価不能回答は履歴・集計で区別する。教材評価は閲覧者に限り全項目の回答を必須とし、現行H4は`phase=posttest`にある教材評価6項目を個別に参照する。仕様版52の対応protocolの回答は評価サマリー追加時にも保存時の内容を維持する。事前回答は事後アンケート・仮説指標へ合算しない。

- `presurvey-baseline-v4`および`presurvey-four-topic-baseline-v4`（仕様版54）: 仕様版55より前に使った版。自己評価に具体例は表示せず、回答項目・尺度・保存形式は現行v5と同じだった。保存済み回答は当時のsurvey_versionで保持し、新規送信には受け付けない。

アプリ内の同意説明を更新しても、研究倫理上の審査・承認を意味しない。尺度の妥当性、回想誤差、回答負担および各モード間の比較可能性は、この実装だけでは検証されていない。
