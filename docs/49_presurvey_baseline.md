# 事前アンケート

## 事前アンケートの現行契約（仕様版48導入、仕様版50更新）

新規参加者は仕様版52 / `experiment-plan-2026-11-12-posttest-system-clarity-removal-v1`で同意後・事前テスト前に回答する。登録snapshotされた問題モードに応じてアンケート版と対象用語を固定する。標準2モードは`presurvey-baseline-v4`、4用語版は`presurvey-four-topic-baseline-v3`を使う。理解度質問は「{用語}の基本的な意味や働きをどの程度理解していますか。」とし、「実験前の時点で」を含めない。見聞き経験の質問にある「実験の説明を受ける前に」は維持する。4用語版の用語表記は問題バンク`split-actions-four-topic-v2`に合わせる。仕様版51以下の参加者・回答は閲覧専用で保全し、新しい質問・用語への変換や遡及適用をしない。現行事後アンケートは[posttest-5point-v4](52_posttest_five_point_evaluation.md)。尺度の妥当性や研究上の承認はこの変更だけでは確認されない。

| 問題モード | アンケート版 | 対象用語 |
| --- | --- | --- |
| `application` | `presurvey-baseline-v4` | 事前学習、ファインチューニング、RAG、プロンプトエンジニアリング、マルチエージェント、記憶プロセス |
| `basic_understanding` | `presurvey-baseline-v4` | 事前学習、ファインチューニング、RAG、プロンプトエンジニアリング、マルチエージェント、記憶プロセス |
| `four_topic_fundamentals` | `presurvey-four-topic-baseline-v3` | Transformer、事前学習、ファインチューニング、人の評価・好みを用いる事後学習、マルチエージェント、記憶プロセス |

4用語版の事前アンケートは、問題モード名が示す4つの大項目ではなく、LLMの学習段階を下位用語（事前学習・ファインチューニング・人の評価や好みを用いる事後学習）に分けて個別に尋ねる。用語の定義や正答に相当する説明は質問内に提示しない。

### 用語の経験・理解度

各用語について、まず「実験の説明を受ける前に見たり聞いたりしたことがありますか」と尋ねる。経験項目は必須で、保存値は次のとおり。

| 表示 | 保存値 |
| --- | --- |
| ある | `experienced` |
| ない | `not_experienced` |
| 覚えていない | `cannot_recall` |

「ある」の場合に限り、「{用語}の基本的な意味や働きをどの程度理解していますか。」を必須表示する。質問に「実験前の時点で」は付けない。これは実験前に回答する質問であることを前提に、理解度を尋ねる表現に統一したもの。見聞き経験を尋ねる質問「{用語}という用語を、実験の説明を受ける前に見たり聞いたりしたことがありますか。」の文面は変更しない。

| 表示 | 保存値 |
| --- | --- |
| 全く理解していない | `not_at_all` |
| 少し理解している | `slightly` |
| ある程度理解している | `moderately` |
| よく理解している | `well` |

「ない」「覚えていない」の場合は理解度を表示せず、`prior_term_understanding`の該当値をJSON `null`として保存する。未提示を低い理解度へ置き換えない。APIも経験と理解度の組合せを検証し、経験が`experienced`なら理解度を必須、それ以外ならnullを要求する。

### 普段のAI利用

- 利用頻度: 直近30日間にAIを利用した日数。0日、1〜3日、4〜8日、9〜20日、21〜30日の5区分を必須回答とし、`ai_usage_frequency_30d`に`0_days`、`1_3_days`、`4_8_days`、`9_20_days`、`21_30_days`として保存する。
- 行動別の自己評価: 目的に合う回答を得る、期待と違う場合に指示や条件を修正する、AIの回答を他資料・情報源で確認する、の3項目を個別に尋ねる。各項目は「全くできない／あまりできない／少しできる／ある程度できる／よくできる」の1〜5、および「評価できない」を選ぶ。「評価できない」は`not_applicable`、数値回答は整数1〜5として`general_ratings.ai_proficiency`へ保存する。

利用頻度・自己評価は全項目必須とする。回答に定義や操作方法の説明は加えない。注意確認問題は設けない。

### API・保存・出力

GET `/api/participants/{id}/presurvey`は参加者の保存済み問題モードに基づき、`survey_version`と`term_items`（各用語の`key`・`label`）を返す。POST同URLは版、用語別経験・理解度、一般AI利用回答を検証し、既存の`ParticipantSurvey`へ`phase=presurvey`およびアンケート版付きで保存する。DB列は追加しない。事前アンケートが未完了なら事前テストを開始できず、保存成功後にpretestへ進む。同一内容の冪等再送は保存済み結果を返し、同じ冪等キーで異なる内容を送ると競合を拒否する。

参加者ログ、アンケートCSV、全体ログCSVおよび対応するExcel出力では、`phase`・`survey_version`・回答JSONを保つ。事前回答は事後アンケートの回答として扱わず、事後評価や仮説指標の入力へ合算しない。

## 旧アンケートと仕様版49の履歴

- `presurvey-baseline-v3`（仕様版48・49）: 標準2モードで見聞き経験と条件付き理解度、普段のAI利用を取得した。理解度質問は「実験前の時点で、{用語}の基本的な意味や働きをどの程度理解していましたか。」だった。仕様版50では保存版v4に進め、新規参加者の表示文のみを更新する。
- `presurvey-four-topic-baseline-v2`（仕様版48・49）: 4用語版の対象6項目に`instruction_tuning` / 「指示チューニング」を使用した。仕様版50はキーを`fine_tuning`、表示を「ファインチューニング」とするv3を使う。過去の値は変換しない。

- `presurvey-baseline-v2`（仕様版37/38等）: 用語知識を「知らない／聞いたことがある／意味を知っている／説明できる」の4択で取得し、保存値は`unknown`、`heard_of`、`knows_meaning`、`can_explain`。一般AI利用は各1〜10評定だった。
- `presurvey-four-topic-baseline-v1`（仕様版44以降の旧4用語形式）: Transformer、LLMの学習段階、マルチエージェント、記憶プロセスの4項目を取得した。
- `presurvey-baseline-v1`（仕様版36）: 用語ごとに「知っていた／知らない」のBooleanを保存した。

これらの保存済み回答は新形式へ変換・補完しない。仕様版49では事後アンケート`posttest-5point-v1`でシステム評価2項目、教材評価6項目、任意自由記述を取得した。現行仕様版52の新規参加者は`posttest-5point-v4`を使用する。教材評価は閲覧者に限り全項目の回答を必須とし、H5を含む事後評価は`phase=posttest`の現行版だけを参照する。事前回答は事後アンケート・仮説指標へ合算しない。

アプリ内の同意説明を更新しても、研究倫理上の審査・承認を意味しない。尺度の妥当性、回想誤差、回答負担および各モード間の比較可能性は、この実装だけでは検証されていない。
