# 00. Project Summary

## システム名

学習ログ駆動型AIチューター  
英語名: Learning-Log-Driven AI Tutor

## 研究テーマ

AI・情報系専門用語の概念理解において、誤概念の再発抑制と支援なし転移を目的とした、学習ログ駆動型AIチューターを設計・実装・評価する。

## 背景

AI・情報系専門用語は、日常語としても使われる語や、近い意味に見える語が多い。たとえば `Attention` は日常語では「注意」だが、Transformerでは入力中のトークン間関係を重み付けして利用する計算機構である。単語を見たことがあることと、専門分野の概念として使えることは別である。

通常の解説では、学習者がその場で正答できるように見えても、類題や別文脈で同じ誤りを再発する可能性がある。本研究は、単なる正答率ではなく、同じ誤概念が再発しないか、足場掛けなしで自力解答できるか、異なる文脈へ転移できるかを測る。

## システムの中核

学習者がAI・情報系専門用語の問題に回答する。システムは回答を正誤判定するだけでなく、誤答の背景にある誤概念タイプを分類する。その後、誤概念タイプと過去ログに基づき、教授方略と足場掛けレベルを決定する。学習者はAIチューターの支援を受けながら学習し、再テストと確認テストで理解の定着を測る。

## 研究上の最重要ポイント

通常のAIチューターとの差は、「AIを使うかどうか」ではない。差は「ログを使って支援を変えるかどうか」である。

### 統制群

- 誤答に対して一般的な解説を提示する
- 過去ログを支援方針に使わない
- 誤概念タイプに応じた教授方略の切り替えをしない
- 足場掛けレベルを動的に調整しない
- 誤概念分類は分析用に内部保存してよい

### 提案群

- 事前テスト、学習セッション、再テスト、確認テストのログを保持する
- 誤概念タイプをM1〜M4に分類する
- 誤概念タイプに応じて教授方略を切り替える
- 理解が進めばL3からL1へ足場掛けを減らす
- 同じ誤概念が再発した場合は、足場掛けレベルを維持し、教授方略を変更する

## 最終誤概念分類

5月18日の研究計画では、日常語混同、類似概念混同、因果誤認、定義暗記、適用条件誤解、表層キーワード依存などの細分化案があった。5月25日の進捗報告では、先行研究に基づく独自の分析枠組みとして次の4分類へ整理された。

| Final | 名称 | 役割 |
|---|---|---|
| M1 | カテゴリー誤分類型 | 概念を本来とは異なる種類のものとして捉えている |
| M2 | 類似概念境界混同型 | 似た概念との違いや境界を区別できない |
| M3 | 表層特徴・キーワード反応型 | 問題文の表面的な単語や語感に反応している |
| M4 | 文脈転移失敗型 | ある文脈では説明できるが、別文脈で使えない |

実装上はM1〜M4を最終分類として固定する。旧分類は `docs/03_misconception_taxonomy.md` の対応表に従って統合する。

## 主評価指標

| 指標 | 意味 |
|---|---|
| 同種誤答再発率 | 事前テストで出た誤概念と同じタイプの誤りが再テストで再び出た割合 |
| 足場掛けなし自力解答率 | 確認テスト条件、つまりヒントなしで正答できた割合 |

## 実装で守るべき思想

- AIの返答は研究ログとして保存する
- AIの判断は必ず構造化JSONとして保存する
- 学習者画面にはM1〜M4などの内部ラベルをそのまま出さない
- 実験条件を壊さないように、自由チャットは制御する
- 最終的にCSVで実験分析できるようにする
- 同じ問題を完全に使い回さず、同じ構成概念を別文面で測る
- 実装の華やかさより、実験フロー、ログ、評価指標の正確さを優先する

## 初期実装スコープ

初期実装の事前テストでは、4語を対象にする。

1. 過学習
2. 汎化
3. Attention
4. Embedding

Token、Fine-tuning、Prompt、RAGはseedとデータモデルで拡張可能な追加候補として残す。

追加候補はLoss、ハルシネーション、正則化である。追加候補はデータモデルとseedで拡張可能にしておくが、MVPの必須対象にはしない。
