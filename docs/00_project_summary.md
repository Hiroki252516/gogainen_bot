# Project Summary

本リポジトリは、卒業研究用の「誤概念タイプと学習ログに基づくAI・情報系専門用語チューター」の仕様・実装リポジトリである。比較対象は、同じ知識資産を参照する通常AIチューター（control）と、学習ログに基づいて教授方略を変えるログ適応型AIチューター（proposed）である。

## Current MVP

新規実験の対象用語は次の3件に固定する。

| slug | 表示名 | RAG対象 |
| --- | --- | --- |
| `llm_knowledge` | LLMに知識を与える方法 | 第3章「LLMに知識を与える」 |
| `multi_agent` | マルチエージェント | 第4章「マルチエージェントとは」 |
| `memory_process` | 記憶プロセス | 第5章「記憶プロセス」 |

LangGraphは今回の対象用語・教材・RAG検索結果から除外する。過去のTransformer等のTerm、問題、ログはDB互換のため削除せず、新規seedでは非アクティブとして扱う。

テスト問題は10択の複数選択で、A〜Cが正解、D〜FがM1、G〜IがM3、Jが「わからない」である。A/B/Cの3つだけを選んだ場合だけ正解、Jは単独選択だけを有効とする。不正解分類はM3、M1、知識不足の順に優先する。

問題バンクは `backend/app/seed/content/learning_content.yml` を正本とする。参加者向けのテスト表示は「テスト」「再テスト1」「再テスト2」とし、内部フェーズ `final_test` の表示も「再テスト1」に統一する。テストと再テスト1は各用語1問、再テスト周回は各用語4バリエーション（5回目以降は4問目を再利用）、学習セッションの確認問題は各段階・各用語5バリエーション（6回目以降は5問目を再利用）とする。

## Misconception taxonomy

| ラベル | 名称 | 本質 |
| --- | --- | --- |
| M1 | 誤信念型 | 単一の命題・信念が誤っており、その信念の修正が必要 |
| M2 | 欠陥メンタルモデル型 | 複数の信念がつながった説明モデル全体の再構成が必要 |
| M3 | カテゴリー誤り型 | 概念を誤った上位カテゴリーに分類しており、正しいカテゴリーへ再配置が必要 |
| M4 | 欠如したスキーマ型 | 必要なカテゴリーや関係に関する知識構造が不足しており、新しいスキーマの構築が必要 |
| unknown | 知識不足 | 「わからない」または判断に必要な知識が不足している状態 |

固定問題はM1/M3/unknownを診断対象とするが、AI内部taxonomyにはM1〜M4を保持する。内部ラベルは被験者画面に表示しない。

## Current implementation boundary

この章の「Current MVP」は、現在のコードとseedが実際に提供する範囲を示す。固定問題の採点、学習段階の遷移、評価値の計算はbackendが正本であり、AI出力は採点結果や遷移を上書きしない。

- `retest` の採点APIは、1回の呼び出しで現在の再テスト回答を処理する。3用語の各1問が全件正解なら `survey` へ進み、それ以外は不正解・未回答用語を次の `learning_targets` に戻して最初の学習URLを返す。サーバーが自動的に学習・再テスト周回を繰り返すループや通知は未実装である。
- `l0_check` と `transfer` はYAML・DB互換の補助データとして残る。回答ログの `attempts.test_round` は初回を `test`、学習後の確認を `retest_1`、次周回を `retest_2` のように保存する。再テスト3用語が全問正解の場合はその満点を最終到達率に代用して追加の確認を省略し、不正解・未回答がある場合は学習セッションへ戻る。完全な転移評価や遅延再テストは将来対応である。
- 評価サマリーには現行のスコア、再発、負担、条件統制のJSONが保存される。一方、M2/M4固定問題の再発率、unknown継続率、転移率、足場掛け削減量など一部の値は現行実装で `null` または未算出である。

将来設計として、遅延再テスト、完全な転移評価、M2/M4を診断する固定問題、管理者による手動修正・削除・監査操作、詳細な群間グラフを追加できる。これらを現行MVPの機能とは扱わない。

## Flow

1. `/start`で実験条件を選び、`/consent`の仮同意書に同意する。
2. 同意後に3用語についてテストを実施する。
3. 正解済み用語を除き、誤答・unknownの用語を学習対象にする。
4. 学習セッションでは共通RAGを参照して教材と確認問題を生成する。proposedだけが学習ログ、誤概念分類、足場掛け情報、過去応答を使う。
5. 再テストAPIで現在の回答を採点し、全問正解なら結果確認後に `survey` へ進む。不正解・未回答用語があれば `learning_targets` に戻り、追加周回は現行UI/APIを研究者またはクライアントから再開する形である。
6. 再テストが満点でない参加者は次の再テスト周回へ進み、満点を確認した参加者だけが追加の確認を省略して仮アンケートへ進む。アンケート送信後に `finish` を確定する。初回テストで学習対象がない場合も、内部 `final_test` を `retest_1` として表示する。

controlにも同じRAG本文を渡すが、個人の履歴・誤概念taxonomy・教授方略情報は渡さない。
