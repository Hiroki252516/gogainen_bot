# 00. Project Summary

## システム名

学習ログ駆動型AIチューター  
英語名: Learning-Log-Driven AI Tutor

## 研究テーマ

AI・情報系専門用語の概念理解において、誤概念の再発抑制と支援なし転移を目的とした、学習ログ駆動型AIチューターを設計・実装・評価する。

## 背景

AI・情報系専門用語は、日常語としても使われる語や、近い意味に見える語が多い。たとえば `Attention` は日常語では「注意」だが、Transformerでは入力中のトークン間関係を重み付けして利用する計算機構である。単語を見たことがあることと、専門分野の概念として使えることは別である。

通常の解説では、学習者がその場で正答できるように見えても、類題や別文脈で同じ誤りを再発する可能性がある。本研究は、単なる正答率ではなく、同じ誤概念が再発しないか、足場掛けなしで自力解答できるか、異なる文脈へ転移できるかを測る。

## システムの中核

学習者がAI・情報系専門用語の問題に回答する。システムは回答を正誤判定するだけでなく、誤答の背景にある誤概念タイプを分類する。その後、誤概念タイプと過去ログに基づき、教授方略と学習ステージを決定する。学習セッションでは、構成用語を確認する用語理解段階から、対象概念全体を説明する概念理解段階へ進む。学習者はAIチューターの支援を受けながら学習し、再テストと最終テストで理解の定着を測る。

## 研究上の最重要ポイント

通常のAIチューターとの差は、「AIを使うかどうか」ではない。差は「ログを使って支援を変えるかどうか」である。

### 統制群

- 誤答に対して一般的な解説を提示する
- 過去ログを支援方針に使わない
- 誤概念タイプに応じた教授方略の切り替えをしない
- 学習ログ、誤概念タイプ、学習ステージに応じた個別化をしない
- 誤概念分類は分析用に内部保存してよい

### 提案群

- 事前テスト、学習セッション、再テスト、最終テストのログを保持する
- 誤概念タイプをM1〜M4に分類する
- 誤概念タイプに応じて教授方略を切り替える
- 用語理解段階で構成用語を確認し、十分なら次の構成用語または概念理解段階へ進める
- 概念理解段階で不十分な場合は用語理解段階へ戻し、同じ誤概念が再発した場合は教授方略を変更する

## 最終誤概念分類

5月18日の研究計画では、日常語混同、類似概念混同、因果誤認、定義暗記、適用条件誤解、表層キーワード依存などの細分化案があった。5月25日の進捗報告では、先行研究に基づく独自の分析枠組みとして次の4分類へ整理された。

| Final | 名称 | 役割 |
|---|---|---|
| M1 | カテゴリー誤分類型 | 概念を本来とは異なる種類のものとして捉えている |
| M2 | 類似概念境界混同型 | 似た概念との違いや境界を区別できない |
| M3 | 表層特徴・キーワード反応型 | 問題文の表面的な単語や語感に反応している |
| M4 | 文脈転移失敗型 | ある文脈では説明できるが、別文脈で使えない |

実装上はM1〜M4を最終分類として固定する。旧分類は `docs/03_misconception_taxonomy.md` の対応表に従って統合する。

## 主評価指標

| 指標 | 意味 |
|---|---|
| 同種誤答再発率 | 事前テストで出た誤概念と同じタイプの誤りが再テストで再び出た割合 |
| 最終テスト正答率 | 学習後にヒントなし・即時フィードバックなしで正答できた割合 |
| 回答時間 | `question_shown_at` から `answered_at` までの秒数 |

## 実装で守るべき思想

- AIの返答は研究ログとして保存する
- AIの判断は必ず構造化JSONとして保存する
- 通常の学習セッション画面にはデバッグ欄として誤概念タイプ、learning_stage、回答判定、teaching_strategyを表示する。教材本文・フィードバック本文には内部ラベルを書かない
- 実験条件を壊さないように、自由チャットは制御する
- 最終的にCSVで実験分析できるようにする
- 2026-06-22時点の現行実装では、L2概念理解問題・再テスト・最終テストで同一の問題文と選択肢セットを使う
- テスト回答と学習ターン回答は、管理画面とCSVで `answer_history` として統合して分析できるようにする
- 実装の華やかさより、実験フロー、ログ、評価指標の正確さを優先する

## 現行実装スコープ

現行実装の事前テストでは、`backend/app/seed/data.py` のseedに合わせた2語を対象にする。

1. LLMの学習段階 (`llm_training_process`)
2. Transformer (`transformer`)

過去仕様ではTransformer、Attention、事前学習、事後学習を含む5語構成を想定していたが、現行MVPでは必須対象から外す。これらは将来の拡張候補または過去仕様として扱い、現行の評価・テスト・画面遷移は2語構成を正とする。

`MAX_LEARNING_TARGETS=5` は上限値として残すが、実際の出題・学習対象数はactive seedの2語で決まる。
