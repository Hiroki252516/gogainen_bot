# 実験の概要と現行仕様

## 仕様版28の現行コード

通常版のPRETEST・RETEST・内部final_testで、設問1・2の両方を保存した後に同じテスト画面内で選択内容と正誤を示し、続行で次の用語へ進む。設定・API・保存・受入条件は[40](40_question_pair_answer_review.md)を参照する。受入条件の自動検証は未実施。

現在のコードは仕様版28 / experiment-plan-2026-10-30-question-review-v1。仕様版27の採用時記録[39](39_split_assessment.md)は保持する。受入検証の実行状況は[14](14_testing_acceptance.md)に記録する。

## 仕様版26で採用した共通の用語注釈（現行版27でも維持）

仕様版26では共通固定辞書learning-glossary-v2の16語を、教材・回答後解説と事前テスト・再テスト（内部final_testを含む）に表示する。AI、事前学習、ファインチューニング、プロンプトエンジニアリング、RAG、データベース、マルチエージェント、タスク、記憶プロセスの9語を注釈から除外する。長い除外語の一部からプロンプト・エージェントを抽出せず、独立して登場した場合は補足する。新規だけ仕様版26・protocol_id=experiment-plan-2026-10-27-test-glossary-v2を保存し、仕様版25以下は既存方針どおり閲覧専用とする。問題・訂正情報・教授プロンプト・AI生成契約・採点・配置は維持し、学習確認の回答上限は1用語・1セッションにつき1回とする。通常版・易しい版の学習確認1/2は、それぞれのテストバンクのpretest_v1/retest_v1を共用する。詳細は[24](24_learning_glossary.md)、版25で採用した問題本文・分類理由は[38](38_round_two_revision.md)。教材600〜800文字は維持する。

Word「卒業研究計画書_6.7挿入済み.docx」とユーザー承認済み実装計画を根拠とする。出典・確定判断・残課題は[20](20_experiment_plan_alignment.md)、指標は[12](12_evaluation_metrics.md)。

## 研究と実装

- 比較は履歴を使う通常AIチューター（control）と、明示的診断・修正対象・訂正情報・taxonomy・タイプ別教授方針を追加するAIチューター（proposed）。統制群の自然な誤り訂正を許容する。
- 対象3概念：llm_knowledge、multi_agent、memory_process。大学生40名/各群20名・原則無作為割付を目標とし、アプリは研究者のA/Bコードを使用する。
- 6仮説：初回の正答率の伸び、満点までの用語別セッション数、用語内不正解数、同種誤答再選択率、教材評価、満点到達割合。記述集計のみ。
- backendが固定採点・分類・方略決定を行う。M1/M3/unknown、M3優先。AIは教材・正答要約・誤答解説のみ。
- 共通説明とunknownは意味や仕組みを説明する。unknownは定義・仕組み・教材内適用確認を本文証拠で検査し、旧6項目を必須としない。
- 両群とも600〜800文字・自由な章立て。実験群の本文証拠検査は意味的な正しさや理解の証明ではない。
- アプリ側既定はgpt-6-luna / low。管理画面でgpt-6.1-sol / gpt-6-lunaを一時切替できる。設定はbackendプロセス内だけに保持し、次回呼び出しから両群・進行中参加者に適用、再起動で環境値へ戻る。実験中の変更は同一参加者内のモデル混在を生み得るため、収集時は固定する。研究計画書原本にはgpt-5.6-luna / lowと記載されており、Wordは変更していない。アプリ標準条件との一致を警告・実送信監査で識別する。実AI失敗時にMockへ切り替えない。
- アンケートは経験4有無、一般4/教材6の1〜10、必須自由記述。教材未表示者の6項目は自動対象外。

## 版・保存・フロー

現行コードは新規参加者に仕様版28とexperiment-plan-2026-10-30-question-review-v1を保存する。版27以下、旧protocol_id、NULL・未対応版は閲覧専用で保全する。既存行へ版・protocol・答え合わせ設定・確認時刻を補完しない。

通常版テストはsplit-actions-v1により、3用語×2設問の6設問・4択単一選択となる。設問3はデータだけ保持し、activeな問題・表示・採点には使わない。易しい版は従来形式。テスト上限・採点・回次・問題内容は[39](39_split_assessment.md)を参照する。答え合わせは通常版のPRETEST・RETEST・内部final_testに適用し、採点は6設問完了後に行う。学習確認と評価式は変更しない。

material-viewの初回表示時刻から実績を数え、未利用の先行生成を学習回数・教材表示者へ算入しない。新アンケート・指標は版付きJSONへ保存し、旧5段階値や既存評価列を変換しない。

## 開始前の残課題

A〜C正解等の配置はデバッグ用であり収集に使わない。管理者認証・アクセス対策、自動割付/人数上限は今回未実装。承認・同意/撤回・割付の運用と配布設定を別途確認する。実装完了だけで実験開始可能とはしない。

検証結果は[14](14_testing_acceptance.md)、切替・運用は[18](18_implementation_blueprint.md)・[19](19_experiment_operation_runbook.md)。過去の資料・検証・生AIログは書き換えない。

## 問題版の切替

現行コードでは通常版と易しい版を並行保持し、問題版を登録時に固定する。仕様版28の答え合わせ設定は通常版の新規参加者に限り登録時に固定し、易しい版には適用しない。各問題版内で両群を比較・集計し、版をまたぐ成績を同等と扱わない。[運用と契約](22_question_set_modes.md)・[問題全文](23_easy_question_bank.md)を参照する。
