# 基礎理解版テスト問題モード（仕様版43の導入記録）

> 本文は仕様版43で導入した基礎理解版の条件記録。現行の第3モード4用語版は[51](51_four_topic_foundation_mode.md)を参照する。仕様版44でも`basic_understanding`の内容・互換性契約は維持する。

## 現行条件

新規参加者は管理画面の登録前設定に従い、`application`（現行版・場面応用）または`basic_understanding`（基礎理解版）のどちらかで開始する。既定値は`application`。値は登録時に`Participant.test_content_mode`へ保存し、その後の管理設定変更では既存参加者の問題・回答・確認問題を切り替えない。RuntimeSettingの設定APIは管理認証を必須とし、適用範囲は新規参加者のみ。

仕様版43のprotocolは`experiment-plan-2026-11-08-basic-understanding-question-mode-v1`。仕様版42以下・旧protocolは閲覧専用で記録を保持し、既存Participantのspec/protocol、問題snapshot、回答、教材、評価を移行・補完しない。NULLの`test_content_mode`は`split-actions-v5`（application既定バンク）として復元する。仕様版43では登録時snapshotが通常保存される想定だが、欠落したNULL値に対しても復元用の既定値を適用し、保存済みsnapshot自体は変更しない。

## 問題バンク

| モード | 問題バンク | 内容 |
| --- | --- | --- |
| `application` | `split-actions-v5` | 従来の場面応用問題 |
| `basic_understanding` | `split-actions-basic-v1` | 基礎理解を直接問う新規問題 |

基礎理解版は`backend/app/seed/content/standard/split_assessment_basic_v1.yml`に保存する。事前テスト・再テスト1・2の計9問（3用語×3回次）を含み、各問は正解1・M1誤答2・M3誤答2・unknown1の6択。新規仕様版43は既存の設問1のみ設定を引き継ぎ、各テストで3用語の設問1、計3問を出題・採点する。設問2・3はこのバンクには含めない。選択肢の配置・固定採点・表示後の注釈は既存規則を使う。

学習確認問題は直前テストで誤答した問題の保存snapshotを再利用し、ライブバンクを参照して過去の問題を書き換えない。内部`final_test`は各モードの再テスト1と同じ問題を使う。教材、教材生成プロンプト、教授方略、群割付、採点規則、テスト回数上限は変更しない。

## 集計と記録

仕様版43の6仮説はテスト問題モードごとに集計し、異なるモード間の値を合算しない。群別集計・参加者別集計・詳細JSONと専用CSV/XLSXにモードを記録する。参加者ログ、全体ログ、参加者テーブルCSVにも登録時の値を出す。統合ログCSVは`test_content_mode`列を追加する。

## 研究上の留意点

基礎理解版は、長い業務場面や複数の設計判断を減らし、RAGと重み、役割分担、会話を越える記録の各基本関係を問うよう作成した。しかし、実際に難易度が下がること、現行版と難易度・測定特性が同等であること、回次間の等価性は検証済みではない。問題は各回で表現を変えるため、同じ学習目標を保つ意図はあるが、同等性を保証しない。測定できる範囲も、対象3用語の限定された基礎理解に限られ、広い応用力や習得全体を示すものではない。

研究者向けの正誤理由・誤答の分類意図は実行時問題データに含めない。問題の教育的妥当性と基礎理解版の採用について、研究上の承認が得られたことを意味しない。収集前に研究者が内容を確認し、必要なら予備調査を行う。

## 検証契約

- 各モードの3回次・3用語・出題対象設問と役割数を検証する。
- 仕様43の新規参加者は指定モードのbank keyだけを取得・採点・復元し、設定変更は既存参加者へ遡及しない。
- 仕様42以前のNULLはv5で履歴復元され、既存snapshotを優先する。
- 管理ログ・参加者CSV・全体／参加者ログCSVとExcelにモードを含める。
- モードが混在する群集計・仮説集計は別々に出力し、統合値を生成しない。
