# 現行画面

## 易しい版の停止（2026-10-30）

管理画面には問題版・集計版の切替を置かず、新規参加者の問題版を通常版と固定表示する。既存easy participantのcurrent-stepは閲覧専用を返し、参加者画面は再開させない。管理者は一覧・個別ログ・CSVから記録を参照できる。群集計・仮説CSVは通常版に限定する。easyの画面・問題資産・保存データは削除しない。[保存/API契約](22_question_set_modes.md)。

## 仕様版28の設問ペア答え合わせ（現行実装）

通常版のPRETEST・RETEST・内部final_testでは、同じ用語の設問1・2を両方保存した後、設問を表示している用語ページ内で2問の正誤を示す。選択した選択肢だけを正解なら緑、不正解なら赤にし、未選択の選択肢は正答・誤答を示さない。答え合わせ開始時にURLや別画面へ移動しない。設問番号と本人の選択内容も同じページに残し、正答選択肢・解説・内部分類・群・方略は表示しない。「次の用語へ」は確認記録を保存し、同じ画面内で次の用語へ進める。最後のペア確認後は既存のフェーズ完了・採点経路へ進む。

「設問ごとの答え合わせ」は初期値ONで、通常版の新規参加者だけに登録時点で固定する。既存の「事前テストの結果表示」は独立し、ONならPRETEST全体結果をペア確認後に表示し、OFFなら省略する。ペア設定がOFFでも既存設定の動作を変えない。RETEST/final_testの全体結果画面はペア設定に関係なく維持する。仕様版27以下にはペア確認を適用しない。実装・保存・再読み込み契約は[40](40_question_pair_answer_review.md)。

## 事前結果表示切替（issue-204）

管理画面の「事前テストの結果表示」は初期値ON、新規参加者のみ適用する。OFFでは事前結果確認画面を挟まず最初の未完了学習へ進み、事前満点なら追加テストへ進む。直接URLでも結果を描画する前に移動する。再テスト・内部final_testの結果表示は維持する。古い診断再送応答にreview_requiredがなければ従来どおり結果確認を表示する。

診断画面でも遷移前にlearning_target_slugsを保存する。過去の非表示用再送応答に一覧がなければ学習対象APIから取得する。結果ページからの非表示遷移も保存を先に行い、自己参照・欠落・許可しない遷移先はエラーで停止する。完了済み対象は既存のassignment処理で一覧から外れ、全完了時は既存処理がretestへ進める。

非表示で結果URLを開き直した際は、同じ参加者の保存済み一覧に残りの対象がすべて含まれていれば、全体の一覧を保持する。途中で分母を残数へ縮めない。別参加者や破損したキャッシュは現在の一覧へ置き換える。

## ページ幅

共通ページと管理画面のロックボタン領域は最大1440pxとし、狭い画面では左右に16pxずつ余白を設ける。管理パスワードダイアログは最大420px、学習画面は760px以下で1列となる従来の表示を維持する。

画面下部に固定表示する主要操作ボタン（「次へ」「回答を確認」など）は、文字18px・最小高56pxとし、広めの余白を設ける。狭い画面では長いラベルを折り返し、画面幅からはみ出さないようにする。固定パネルとボタンの既存配置は維持する。

## 問題の段落表示

通常版のテストは新規参加者のみ、同じ用語の設問1・2を1ページにまとめ、3用語を3ページで進める。事前・再テスト・内部final_testに適用する。共通場面の完全一致と設問境界を確認できるときだけ場面を一度表示し、そうでなければ本文をそのまま表示する。各設問は別の単一選択として回答し、両方の回答後にページを保存する。設問ごとの注釈は1つの欄へ統合し、同一注釈を重複表示しない。再読み込みは保存済み回答をロックして最初の未完了ページへ戻る。ページ時間は同じ回答・時刻を用いて冪等再送する。

通常版の学習確認問題で複数設問を同じ画面に表示する場合、各保存本文の先頭にある場面説明が完全一致し、空行と「設問1：」「設問2：」の境界を判別できるときは、画面上では場面説明を問題見出しの直下に1回だけ表示する。設問ごとの番号・見出し・問い・選択肢は維持する。単問、不一致、境界不明の場合は保存本文をそのまま表示する。この整理は表示時のみで、API・保存本文・snapshotを変更しない。

学習turnに確認問題が欠落している場合、画面はクラッシュさせず、問題本文と再読み込み案内を表示する。選択肢・回答送信は無効とし、欠落データを回答として記録しない。

仕様版25で採用したLLM知識・記憶の確認V2と3用語の再テストV2の本文・段落表示を、版26でも維持する。LLM確認は2段落、記憶確認は3段落、LLM再テストは5段落、マルチ再テストは4段落、記憶再テストは2段落とする。改行表示条件は今回の5問だけを追加・更新し、旧本文と他の問題の表示を維持する。太字や重複する問題ラベルは保存しない。[全文と検証条件](38_round_two_revision.md)。

仕様版20で採用した通常版マルチエージェント・記憶プロセスの再テストV1/V2へ既存preserve-linesを追加する。マルチエージェントV1と記憶V2は場面3段落・設問の4段落、残る2問は場面・設問の2段落。段落内の途中改行はつなぎ、太字・装飾用Markdown・重複する場面/問題見出しは保存しない。用語・改訂文の導入と設問段落で今回の4問を限定する。内部final_testも改訂V1を共用する。前回のLLM知識の確認V1/V2・再テストV1/V2の表示、易しい版・旧問題・他問題は維持する。[今回の全文と検証条件](33_multi_memory_retest_revision.md)・[LLMの採用時記録](32_llm_confirmation_retest_revision.md)。

通常版memory_process・V1は、大学・学生の説明、開発担当者の目的、設問を空行で区切る既存の3段落表示を維持する。用語・variant番号1・導入文と開発担当者の段落で対象を限定する。[V1の採用時記録](30_memory_confirmation_revision.md)。

既存の通常版multi_agent・V2/V3は案1・案2の段落とvariant番号2/3で限定する改行表示を維持する。V3は仕様版16で改訂した5段落の問題で、通常進行は最大2周のままなので出題されない。検証用の3回目セッションは隔離DBだけに用意する。[V3](29_multi_agent_round_three_revision.md)・[V2](28_multi_agent_round_two_revision.md)。

## 用語の補足

教材と事前/再テスト（内部final_testを含む）の注釈は、幅1100px以上では本文の右側に追従する欄、幅1100px未満ではボタンで開閉するパネルに表示する。回答後解説の注釈は解説の下に表示する。テストは問題文・全選択肢・用語見出しから抽出し、回答を選ぶ前から同じ一覧を利用できる。空配列・保存値欠落時は欄やボタンを出さず、確認問題自体・結果確認には表示しない。両群・両問題版共通で、注釈の内容・保存方式は変えない。表示変更は進行中の参加者にも適用されるため、実験途中の適用は条件変更として記録する。テストの案内は「正誤や正解の解説は表示されません」とする。[24](24_learning_glossary.md)。

## 現行の画面要件

参加者画面では、事前テストから終了まで、ヘッダー直下に実験全体の工程進捗メーターを表示する。メーターは横長バー、工程名、％で構成し、事前テスト0％、事前後1回目まで25％、事前後2回目まで50％、アンケート75％、終了100％とする。これは工程の進み具合であり、回答数・理解度・得点ではない。100％も実験手続きの完了を示し、満点到達を意味しない。

テスト結果の確認画面では工程名を「テストの結果確認」とし、％は保存済みの次工程に合わせる。初回満点などで工程を飛ばす場合は、その次の保存状態に対応した割合を表示する。開始・同意・管理画面には出さず、スクロール固定や工程間の移動操作も設けない。既存のテスト問題番号、用語ごとの学習進捗、残り挑戦回数は維持する。

進捗は `current-step` の読み取り専用応答から取得し、定期ポーリングやブラウザー内カウンターは使わない。読み込み中は割合を表示せず、取得失敗時は再取得ボタンを出すが、回答や画面操作を止めない。旧試用・対応する進捗がない場合は表示しない。進捗バーは読み上げ可能にする。

2026-10-21追加: /consentにはユーザー提示の同意書全文・必須の学籍番号・同意チェックを表示する。責任者・保存場所・保管期間は保留中のため動作確認用と明示するが、ユーザー指定により新規登録を可能とする。管理画面には対応表の表示・CSV取得・個別/全件削除を追加する。削除は確認ポップアップを経由し、対応表だけの削除と研究データの削除を区別する。当時は管理者認証を追加していなかった。2026-10-27に管理画面の伏せ字パスワード入力ポップアップ（既定abc）を追加し、認証成功後にだけ管理画面を表示・データ取得する。キャンセルは/startへ戻り、再入場・再読込は再入力、ロックはサーバーのセッションも失効させる。[管理APIの保護](15_security_privacy.md)。

両群で回答形式・正誤表示・挑戦上限・再学習/終了規則・画面構成を共通とする。事前後のテストは学習前final_testも含め最大2回、事前込み最大3回。1回目未達は再学習、2回目未達は未達のままアンケートへ進み、結果画面に「事前テスト後のテストを2回実施しましたが、満点には届きませんでした」と案内する。満点なら早期終了する。管理画面では共通回数/上限と学習後retest回数を区別する。教材の章立てはAI生成し、検査用JSON・内部分類は参加者に見せない。

現行surveyは利用経験4有無、一般4/教材6の整数1〜10、必須自由記述を扱う。[項目・端点](12_evaluation_metrics.md#アンケートの目標)を参照する。GET surveyのサーバー判定で未表示者の教材6項目を非表示・自動対象外とする。その他は全員必須。教材描画後の可視状態でmaterial-viewを送り、回答時にも再送して表示記録を確保する。

## 現行実装

start / consent / pretest / diagnosing / learning-targets / learning/[termSlug] / retest / final-test / survey / finish / adminを使う。廃止した追加確認ページは404。

ParticipantFlowGuardはcurrent-stepを確認する。旧試用は回答・生成を始めず閲覧専用案内と「新しい実験を開始」を表示する。新規開始はブラウザのparticipant_id、display_code、learning_targets、保留参加コード、保留送信を消すだけでDBを削除しない。

回答は10チェックボックス。表示ラベルにかかわらず、正しい説明を3つ、または「わからない」1つだけを選ぶ。排他選択はAPIの `exclusive` 情報で扱い、A〜I/Jの固定位置に依存しない。上限・回答済みロック、実測時刻、冪等送信を維持する。理由欄・自由回答・単一選択・項目別問題はない。

テスト結果確認は全問正解時も表示し、選択内容と正誤を示す。内部ラベル・群・方略を表示しない。学習では用語進捗と残り挑戦回数、教材・確認問題、回答後の正誤とAI解説を表示する。回答後は正解選択肢を緑、不正解選択肢を選択状態にかかわらず赤で示す。回答前には正誤を示さない。Markdown描画と次教材への解説非混入を維持する。

再テスト・内部final_test、学習、再テスト結果確認に表示する実験ギブアップ操作は、ヘッダー右側で管理画面リンクの左隣に配置する。通常のページフローに置き、スクロール時はヘッダーとともに画面外へ移動する。狭い画面ではヘッダー内で折り返すが、ギブアップ操作と管理画面リンクの順序・隣接を保つ。表示条件、確認・送信・エラー処理、遷移先は維持する。

教材内の###小見出しは両群ともAIが生成する。文言・数・順序・まとめ方を画面で固定せず、生成Markdownをそのまま描画する。冒頭の##用語名、画面側の教材/問題ラベル、回答後解説の見出しは維持する。章立て監査と必須証拠の内部JSONは参加者へ表示しない。

管理画面は旧試用を明記して現行群集計から除外し、再計算と削除を無効化する。現行参加者数と旧試用数を別々に表示し、全体の評価サマリーは現行参加者だけを対象とする。過去の保存済み評価は個別ログから閲覧でき、回答履歴には試用区分を表示する。過去値は履歴用表示に隔離する。

AI設定欄では推論レベルに加えGPT-6.1 Sol / GPT-6 Lunaを選べる。モデル・推論レベルどちらかの更新中は両方の切替ボタンを無効化する。Mockではモデル切替を無効にし、モデルが実利用中でないことを表示する。管理上書きはbackend内だけに保持され、次回のAI呼び出しから有効、backend再起動で環境設定へ戻る。実験中の切替は同一参加者内でモデルが混在し得るため、実験開始前に固定する。

管理画面の選択肢配置設定で「デバッグ配置」と「ランダム配置」を切り替える。モード設定はDBに保存され、新規参加者の開始時に固定される。ランダム配置では「わからない」を最後のJに固定し、残る9択をA〜Iへ並べ替えることを管理画面にも表示する。単独選択の処理は表示ラベルではなくexclusiveを使い続け、以前の並びで保存された学習問題も再表示・採点できる。保存済みsnapshotは変更しない。デバッグ配置は正解位置の手掛かりとなるため、デバッグ時だけ使用し、実験データ収集前にランダム配置を選ぶ。管理画面の既存アクセス制御は本設定追加では変更しない。

## 通常版の現行画面

新規参加者は通常版のみ。問題版・集計版の管理切替はなく、集計は通常版に限定する。既存easy participantは閲覧専用だが、参加者一覧・個別ログ・参加者別CSV・全件生ログには残す。停止前に保存した易しい版の回答・snapshot・評価・問題バンクは変更しない。[停止後の運用](22_question_set_modes.md)を参照する。
