# 現行画面

## 通常版マルチエージェント確認問題V2・V3の表示

通常版multi_agentのV2と、仕様版16で改訂するV3は案1・案2などの段落を空行で区切り、既存preserve-linesで改行表示する。V3は導入文・案1・案2・検索ツールの説明・設問の5段落とする。太字・Markdown記号・重複する「問題：」は付けない。公開APIの既存情報（用語・variant番号2/3・本文の案1/案2段落）で対象を限定し、易しい版、通常版V1、他用語やテストの表示は変更しない。通常の最大2周ではV3は出題されず、検証用の3回目セッションは隔離DBだけに用意する。小画面での折り返し・非重複・横はみ出しを確認する。[全文と検証条件](29_multi_agent_round_three_revision.md)・[V2](28_multi_agent_round_two_revision.md)。

## 用語の補足

学習画面だけで、教材と回答後解説のそれぞれの下に、APIのglossary.entriesを定義リストとして常時表示する。語の出現順・説明文はbackendの保存snapshotに従う。空配列・旧記録の欠落時は欄を出さない。本文の下線・括弧挿入・開閉操作はなく、問題・選択肢・テスト・結果確認には表示しない。両群・両問題版に同じ表示を適用し、小画面で折り返す。[24](24_learning_glossary.md)。

## 現行の画面要件

参加者画面では、事前テストから終了まで、ヘッダー直下に実験全体の工程進捗メーターを表示する。メーターは横長バー、工程名、％で構成し、事前テスト0％、事前後1回目まで25％、事前後2回目まで50％、アンケート75％、終了100％とする。これは工程の進み具合であり、回答数・理解度・得点ではない。100％も実験手続きの完了を示し、満点到達を意味しない。

テスト結果の確認画面では工程名を「テストの結果確認」とし、％は保存済みの次工程に合わせる。初回満点などで工程を飛ばす場合は、その次の保存状態に対応した割合を表示する。開始・同意・管理画面には出さず、スクロール固定や工程間の移動操作も設けない。既存のテスト問題番号、用語ごとの学習進捗、残り挑戦回数は維持する。

進捗は `current-step` の読み取り専用応答から取得し、定期ポーリングやブラウザー内カウンターは使わない。読み込み中は割合を表示せず、取得失敗時は再取得ボタンを出すが、回答や画面操作を止めない。旧試用・対応する進捗がない場合は表示しない。進捗バーは読み上げ可能にする。

2026-10-21追加: /consentにはユーザー提示の同意書全文・必須の学籍番号・同意チェックを表示する。責任者・保存場所・保管期間は保留中のため動作確認用と明示するが、ユーザー指定により新規登録を可能とする。管理画面には対応表の表示・CSV取得・個別/全件削除を追加する。削除は確認ポップアップを経由し、対応表だけの削除と研究データの削除を区別する。管理者認証は未追加。

両群で回答形式・正誤表示・挑戦上限・再学習/終了規則・画面構成を共通とする。事前後のテストは学習前final_testも含め最大2回、事前込み最大3回。1回目未達は再学習、2回目未達は未達のままアンケートへ進み、結果画面に「事前テスト後のテストを2回実施しましたが、満点には届きませんでした」と案内する。満点なら早期終了する。管理画面では共通回数/上限と学習後retest回数を区別する。教材の章立てはAI生成し、検査用JSON・内部分類は参加者に見せない。

現行surveyは利用経験4有無、一般4/教材6の整数1〜10、必須自由記述を扱う。[項目・端点](12_evaluation_metrics.md#アンケートの目標)を参照する。GET surveyのサーバー判定で未表示者の教材6項目を非表示・自動対象外とする。その他は全員必須。教材描画後の可視状態でmaterial-viewを送り、回答時にも再送して表示記録を確保する。

## 現行実装

start / consent / pretest / diagnosing / learning-targets / learning/[termSlug] / retest / final-test / survey / finish / adminを使う。廃止した追加確認ページは404。

ParticipantFlowGuardはcurrent-stepを確認する。旧試用は回答・生成を始めず閲覧専用案内と「新しい実験を開始」を表示する。新規開始はブラウザのparticipant_id、display_code、learning_targets、保留参加コード、保留送信を消すだけでDBを削除しない。

回答は10チェックボックス。表示ラベルにかかわらず、正しい説明を3つ、または「わからない」1つだけを選ぶ。排他選択はAPIの `exclusive` 情報で扱い、A〜I/Jの固定位置に依存しない。上限・回答済みロック、実測時刻、冪等送信を維持する。理由欄・自由回答・単一選択・項目別問題はない。

テスト結果確認は全問正解時も表示し、選択内容と正誤を示す。内部ラベル・群・方略を表示しない。学習では用語進捗と残り挑戦回数、教材・確認問題、回答後の正誤とAI解説を表示する。Markdown描画と次教材への解説非混入を維持する。

教材内の###小見出しは両群ともAIが生成する。文言・数・順序・まとめ方を画面で固定せず、生成Markdownをそのまま描画する。冒頭の##用語名、画面側の教材/問題ラベル、回答後解説の見出しは維持する。章立て監査と必須証拠の内部JSONは参加者へ表示しない。

管理画面は旧試用を明記して現行群集計から除外し、再計算と削除を無効化する。現行参加者数と旧試用数を別々に表示し、全体の評価サマリーは現行参加者だけを対象とする。過去の保存済み評価は個別ログから閲覧でき、回答履歴には試用区分を表示する。過去値は履歴用表示に隔離する。

AI設定欄では推論レベルに加えGPT-6.1 Sol / GPT-6 Lunaを選べる。モデル・推論レベルどちらかの更新中は両方の切替ボタンを無効化する。Mockではモデル切替を無効にし、モデルが実利用中でないことを表示する。管理上書きはbackend内だけに保持され、次回のAI呼び出しから有効、backend再起動で環境設定へ戻る。実験中の切替は同一参加者内でモデルが混在し得るため、実験開始前に固定する。

管理画面の選択肢配置設定で「デバッグ配置」と「ランダム配置」を切り替える。モード設定はDBに保存され、新規参加者の開始時に固定される。ランダム配置では「わからない」を最後のJに固定し、残る9択をA〜Iへ並べ替えることを管理画面にも表示する。単独選択の処理は表示ラベルではなくexclusiveを使い続け、以前の並びで保存された学習問題も再表示・採点できる。保存済みsnapshotは変更しない。デバッグ配置は正解位置の手掛かりとなるため、デバッグ時だけ使用し、実験データ収集前にランダム配置を選ぶ。管理画面の既存アクセス制御は本設定追加では変更しない。

## 通常版・易しい版

管理画面に新規参加者向け問題版の二択と、独立した集計版の二択を置く。配置二択とは別設定である。参加者一覧・履歴に版を表示し、群集計・6仮説・人数・仮説CSVは集計版に限定する。参加者の途中切替は行わない。[22](22_question_set_modes.md)を参照する。
