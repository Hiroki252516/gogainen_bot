# 09. Frontend UX Flow

## 基本方針

- 研究実験用UIとして、誤操作防止と記録の完全性を優先する
- 被験者には内部ラベルを見せない
- テストフェーズではヒント、チャット、即時正誤表示を出さない
- 事前アンケートは表示しない
- L0確認と転移テストは現行参加者フローから外す

## Page List

### `/start`

被験者開始画面。

- 研究システムの簡単な説明
- 同意チェック
- 管理者用のgroup condition選択
- 開始ボタン

個人名やメールアドレスは入力させない。

### `/pretest`

5問の事前テスト。

表示:

- 問題文
- 選択肢
- 次へ

禁止:

- 正誤表示
- ヒント
- 解説
- チャット欄
- 理由記述欄
- 自信度入力欄

最後の問題送信後 `/diagnosing` へ進む。

### `/diagnosing`

AI診断中画面。内部Mラベルは表示しない。成功後 `/learning-targets` へ進む。

### `/learning-targets`

正答以外の全学習対象を表示する。現行5問版では最大5件。

表示:

- 対象概念名
- 自然言語の確認ポイント
- 学習開始ボタン

### `/learning/[termSlug]`

1対象概念の学習画面。`group_condition` によりUIを分岐する。

#### 提案群

前提用語ゲート型UI。

```text
対象概念
  ↓
前提用語カード
  ↓
記述式確認
  ↓
passなら次の前提用語
  ↓
全pass後、概念理解カード
  ↓
対象概念の記述式説明
  ↓
passなら次対象へ
```

表示:

- 対象概念名
- 現在の段階
- 前提用語名
- 教材
- 確認質問
- 回答欄
- AIフィードバック
- 再説明/例
- 概念理解教材
- 残り試行回数
- 次の対象概念へ進むボタン

#### 統制群

通常AIチューターUI。

表示:

- RAG教材に基づく一般説明
- 自己説明prompt
- 回答欄
- 一般的フィードバック
- 次の対象概念へ進むボタン

統制群では前提用語リスト、ゲート進行、誤概念に応じた説明を表示しない。

### `/retest`

即時再テスト。再テストが現行フローの最終テストである。

- チャット不可
- ヒント不可
- 結果は即時表示しない
- 学習対象用語だけを出す
- 正式 `retest_v1` を使う
- 選択式のみ
- 理由欄と自信度欄は表示しない

完了後 `/survey/post` へ進む。

### `/survey/post`

主観評価。

- 分かりやすさ
- 使いやすさ
- ヒント量の適切さ
- 自由記述

### `/finish`

実験終了画面。正答率や内部診断結果は表示しない。

### `/survey/pre`, `/l0-check`, `/transfer-test`

旧互換ページ。現行参加者フローでは遷移しない。直接アクセスされた場合は `/pretest` または `/retest` 後の正しい導線へ戻す。

### `/admin`

管理者画面。

- 被験者一覧
- 実験進捗
- 群条件
- 学習対象用語
- 誤概念タイプ分布
- 前提用語ゲートのpass/fail
- AI診断失敗ログ
- Codex app-server接続状態
- CSV出力

## UI文言変換

内部ラベルを被験者用に変換する。

| 内部 | 被験者向け表示例 |
|---|---|
| M1 | 概念を少し別の種類のものとして捉えている可能性があります |
| M2 | 似ている用語との違いを確認します |
| M3 | 言葉の表面ではなく、仕組みに注目して確認します |
| unknown | まず基本的な意味から確認します |

## Validation

- 選択式問題は選択必須
- 事前テストと再テストでは理由記述と自信度を要求しない
- 提案群の用語理解と概念理解は記述必須
- 統制群の自己説明は記述必須
- 二重送信を防ぐ
- 送信中はボタンをdisabledにする

## Accessibility

- キーボード操作可能
- フォームラベルを明示
- コントラスト確保
- 長文問題でレイアウト崩れしない
