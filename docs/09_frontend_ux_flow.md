# 09. Frontend UX Flow

## 2026-06 Iterative UX Update

学習対象画面は「今回残っている確認項目」を表示する。再テストで正解した用語は次周回から消え、未達項目だけが学習対象として残る。学習対象が0件になった場合は `/final-test` へ進む。最終テスト後は `/survey` のアンケート遷移画面へ進む。


## 2026-06 Learning-Session Misconception UI Update

学習画面のデバッグ欄では、事前テスト由来の誤概念と学習セッション内の誤概念を分けて表示する。

- `事前テスト由来の誤概念`: `initial_misconception_type`
- `学習内の現在判定`: 直近回答の `learning_misconception_type` または次ターンの `latest_learning_misconception_type`
- `学習内判定履歴`: `session_misconception_history` を `人間評価 unknown / 報酬モデル M2` のように表示

教材本文やフィードバック本文には、引き続きM1〜M4などの内部ラベルを直接出さない。


## 2026-06 Stage-Based Learning UI Update

`/learning/[termSlug]` では、固定の「ターン: x / 3」と被験者画面の「足場掛けレベル: Lx」を表示しない。代わりに以下を表示する。

- `段階: 用語理解` または `段階: 概念理解`
- 用語理解段階では `用語: 事前学習 1 / 3` や `用語: Attentionレイヤー 1 / 3` のように構成用語と進捗を表示する
- 概念理解段階では対象概念全体を説明することを示す
- デバッグ欄には `誤概念タイプ判定`, `learning_stage`, `回答判定`, `teaching_strategy` を表示する

回答後、継続する場合は単独フィードバック枠を出さずに次ステージ/次構成用語の教材へ自動遷移する。最終完了時のみ教材フィードバック画面を表示する。


## 基本方針

- 研究実験用UIとして、誤操作防止と記録の完全性を優先する
- 教材本文・フィードバック本文には内部ラベルを混ぜない。ただし学習セッションのデバッグ欄には誤概念タイプ判定、learning_stage、回答判定、teaching_strategyを表示する
- テストフェーズではヒント、チャット、即時正誤表示を出さない
- 入力途中の離脱に備えて回答保存状態を明確にする
- 管理画面では研究者がログと診断根拠を確認できるようにする

## Page List

### `/start`

被験者開始画面。

表示:

- 研究システムの簡単な説明
- 同意チェック
- 管理者用のgroup condition選択またはランダム割当ボタン
- 開始ボタン

注意:

- 個人名やメールアドレスは入力させない
- 実験条件名は管理者モードでのみ表示する

### `/pretest`

事前テスト。

表示:

- 1問ずつ表示
- 問題文
- 選択肢
- 記述欄なし
- 自信度入力なし
- 次へ

禁止:

- 正誤表示
- ヒント
- 解説
- チャット欄

送信時:

- 回答を即保存
- 最後の問題送信後 `/diagnosing` へ進む

### `/diagnosing`

AI診断中画面。

表示:

- 「回答を整理しています」のような自然な文言
- 内部Mラベルは表示しない
- app-server失敗時は管理者に知らせる導線を出す

成功後 `/learning-targets` へ進む。

### `/learning-targets`

学習対象一覧。

通常の学習セッション画面ではデバッグ欄に誤概念タイプ判定、learning_stage、回答判定、teaching_strategyを表示する。ただし教材本文、問題文、フィードバック本文には内部ラベルを混ぜない。

表示例:

```text
今回重点的に確認する内容

1. 転移学習: 学習済みモデルを別タスクへ活用する点を確認します。
2. LLMの学習段階: 事前学習、インストラクションチューニング、事後学習の違いを確認します。
```

表示:

- その時点で残っている未達用語
- 各用語の自然言語の確認ポイント
- 開始ボタン

### `/learning/[termSlug]`

1用語の学習画面。

画面構成:

```text
┌──────────────────────────────┐
│ 対象用語・前回回答             │
├──────────────┬───────────────┤
│ 教材           │ 問題              │
├──────────────┴───────────────┤
│ 回答欄・自己説明欄             │
├──────────────────────────────┤
│ 回答確認・次へ                 │
└──────────────────────────────┘
```

必須UI:

- 教材エリア
- 問題エリア
- 学習者回答欄
- 自己説明欄
- 学習ステージ表示
- 用語理解段階では構成用語名と進捗
- セッション完了後の次の用語へ進むボタン
- 自信度入力なし
- デバッグ用の誤概念タイプ判定
- デバッグ用の `learning_stage`
- デバッグ用の `teaching_strategy`
- デバッグ用の回答判定

回答確認後:

- AIフィードバックを単独の通知枠として表示しない
- 継続ターンがある場合は自動で次ターンを生成し、回答欄を空にする
- 前ターンの問題、あなたの回答、フィードバックは次ターン教材の冒頭に統合する
- `concept_understanding` で `is_sufficient = true` の場合だけ、問題なしの教材フィードバック画面を表示してから次の用語・再テストへ進める
- 回答後のデバッグ欄は `next_learning_stage` と回答判定を即時反映する

チャット制御ボタン:

- もう少し簡単に
- 例を見たい
- 反例を見たい
- 違いを比較したい
- 自分の説明を確認して

禁止入力への返答:

```text
この実験では、正解だけを提示することはできません。
代わりに、考えるための観点を1つ示します。
```

### `/retest`

即時再テスト。

- チャット不可
- ヒント不可
- 選択式
- 理由記述欄なし
- 結果は即時表示しない
- 学習対象用語だけを出す
- 事前テストと同じ文面は使わない

完了後 `/l0-check` または2回目学習が必要なら `/learning-targets` へ進む。

現行実装では、再テスト採点後に未達用語が残っていれば `/learning-targets`、残り0件なら `/final-test` へ進む。

### `/final-test`

最終テスト。

- 現行seedの2用語すべてを出題する
- 選択式
- 理由記述なし
- チャット不可
- ヒント不可
- 即時正誤表示なし
- 採点後 `/survey` へ進む

### `/l0-check`

確認テスト。

- ヒントなし
- 解説なし
- チャット欄なし
- 自由記述中心
- 理由記述必須
- 即時正誤表示なし

### `/finish`

終了画面。

表示:

- 実験終了メッセージ
- 被験者ID
- 管理者へ知らせる案内

正答率や内部診断結果は表示しない。

### `/survey`

アンケート遷移画面。現行実装では「アンケート画面は次の実装で接続します」と表示し、`/finish` へ進む暫定画面である。

### `/admin`

管理者画面。

表示:

- 被験者一覧
- 実験進捗
- 群条件
- 学習対象用語
- 誤概念タイプ分布
- AI診断失敗ログ
- Codex app-server接続状態
- CSV出力
- データ削除

管理者だけに表示してよいもの:

- M1〜M4
- L1〜L3
- recurrence_flag
- AI診断JSON
- diagnosis_confidence
- manual review flag

ログ表示:

- 全体ログを見る
- 全体ログCSV
- 被験者ログを見る
- 被験者ログCSV

既存のテーブル別CSVリンクは管理画面の主導線から外す。画面上では、全体ログと被験者別ログで実験経過を追えるようにする。

## UI文言変換

内部ラベルを被験者用に変換する。

| 内部 | 被験者向け表示例 |
|---|---|
| M1 | 概念を少し別の種類のものとして捉えている可能性があります |
| M2 | 似ている用語との違いを確認します |
| M3 | 言葉の表面ではなく、仕組みに注目して確認します |
| M4 | 別の場面でも同じ考え方を使えるか確認します |
確認テストではヒントなしで回答させる。`L1/L2/L3` は互換ログ用の内部値であり、被験者画面には直接表示しない。

学習セッションのデバッグ表示:

- 通常の被験者画面にも、誤概念タイプ判定、`learning_stage`、回答判定、`teaching_strategy` を表示する
- 表示目的は開発・実験運用中の確認であり、CSVや管理画面のログ保存を代替しない
- 教材本文やフィードバック本文では、内部ラベルを説明文に混ぜず自然言語の説明を使う

## Validation

全回答フォーム:

- 選択式問題は選択必須
- 理由記述は20文字未満でも保存するが、短すぎる警告を出してよい
- 事前テストと学習セッションでは自信度入力を表示しない
- 二重送信を防ぐ
- 送信中はボタンをdisabledにする

## Accessibility

- キーボード操作可能
- フォームラベルを明示
- コントラスト確保
- 長文問題でレイアウト崩れしない

## Admin Safety

削除・手動修正には確認ダイアログを出す。

手動修正対象:

- is_correct
- diagnosed_status
- misconception_type
- diagnosis_confidence
- requires_manual_review

修正理由を必須にし、`audit_events` に保存する。

## RAG教材参照

学習ターン生成と学習回答フィードバックでは、`rag_ready_教材` のローカルTF-IDF検索結果を `rag_context` としてAIBackend payloadへ渡す。OpenAI APIキーや外部vector storeは通常実行に使わない。RAG資産が見つからない場合は空のcontextとして扱い、実験フローを停止しない。
