# Frontend UX Flow

## テスト画面

pretest、retest、final-testは新しい3用語を表示する。固定問題は10択複数選択で、A〜Iから3つ、またはJ「わからない」だけを選ぶ。Jと他の選択肢を同時選択できないようにし、テスト中は正誤・ヒント・解説を表示しない。

retestとlearning確認問題は、同じ問題文をそのまま繰り返さないためにYAMLのvariant_keyを順番に使う。上限後は指定された最後のバリアントを再利用する。

## 学習画面

学習画面は対象概念、学習段階、教材、確認問題、回答結果を表示する。教材と回答後のフィードバックは安全なMarkdownとして描画し、教材は「要点」「具体例」「注意点」を中心に構造化する。M1〜M4、unknown、教授方略、RAGの内部情報は被験者画面へ出さない。

学習本文とフィードバックは段落・箇条書き・見出し・太字を保持できる表示にし、raw HTML、表、コードブロック、画像は描画しない。既存のプレーンテキスト本文は通常の段落として表示する。内部ログ用の分類値をUIへ混ぜない。controlとproposedの差は被験者に表示せず、backendのAI call logで検証する。

学習セッションの初回読み込み中は、単独の「読み込み中...」ではなく、スピナーと経過秒数を含む進捗カードを表示する。進捗文言は「学習セッションを準備しています」「教材を生成しています」「確認問題を準備しています」「学習画面を表示しています」の4段階とし、一定時間ごとに表示中の段階を進める。これは利用者向けの状態説明であり、AIの内部思考、RAG検索内容、内部診断ラベルを表示しない。読み込みが完了したらカードを消し、教材と確認問題を表示する。APIエラー時は進捗カードを停止し、既存のエラーメッセージを表示する。

回答を送信した後も、同じ画面に問題文と選択肢を残す。選択内容を変更できない状態にして、その直下に正解・不正解と教材フィードバックを表示する。処理中は選択肢を無効化し、スピナーと経過秒数を含む進捗カードを表示する。

回答後の「次の確認へ」を押して次ターンを取得している間も、直前の問題、選択内容、正誤・解説カードを保持したまま、同じ4段階の進捗カードを追加表示する。取得中はボタンを無効化し、「次の確認を準備中...」と表示する。次ターンの取得が完了したら進捗カードと直前のフィードバックを新しい教材・確認問題に置き換える。取得エラー時は進捗カードを停止し、直前のフィードバックとエラーメッセージを表示する。

学習画面には確認ダイアログ付きの「学習をギブアップして再テストへ」ボタンを表示する。実行時は現在の学習セッションを終了し、回答を保存せず`/retest`へ遷移する。再テスト画面と、再テスト後の結果確認画面には「実験をギブアップして終了」ボタンを表示する。確認後は`/finish`へ遷移し、再テスト・学習の問題操作へ戻らない。これらのボタンは回答・次の問題操作から離れた画面下部の右寄せ領域に置く。テスト画面、事前テスト結果画面、アンケート画面、終了画面にはこれらのボタンを表示しない。

テストまたは再テストを解き終えた後の `/learning-targets` では、直近の周回名（`テスト`、`再テスト1`、`再テスト2` など）と3用語分の結果を表示する。各用語について問題文、本人が選んだ選択肢のラベルと本文、正解・不正解・未回答を表示するが、正答、期待解答、選択肢ごとの正誤は表示しない。再テスト不正解時は未達対象の最初の用語へ、満点時はアンケートへ遷移する。内部のM分類や診断履歴は表示しない。

確認問題の送信中は、ボタンを「分析中...」へ変更し、選択肢を無効化する。画面にはスピナー、経過秒数、「回答を記録しています」「選択内容を確認しています」「解説を生成しています」「次の教材を準備しています」という安全な処理状態だけを表示する。AIの内部思考過程や推論中の文章は表示しない。処理完了後は、正誤カード内に正答・誤答に応じたMarkdown解説、`item_results`（値がある場合のみ）、次の確認へのボタンを表示する。現行の固定複数選択フローでは `item_results` は空配列で返る。

旧用語Transformerの新規導線は作らないが、過去URL・DBログの互換性は維持する。

## 管理画面

管理画面は `control` / `proposed` の群タブを持ち、初期表示は `control` とする。選択中の群に応じて、集計、回答履歴、評価サマリー、再発イベント、AI呼び出しログ、被験者一覧をその群だけに絞り込んで表示する。群を切り替えたときは、表示中の被験者別ログを解除する。

全体ログには「誤概念推移（群集計）」を表示し、選択中の群について3用語ごとの解消、同種再発、別タイプ化、unknown継続、後戻り、未分類を人数と割合で示す。割合の分母は用語ごとの事前テスト実施者とし、未受験者は別に表示する。参加者別の誤概念推移表示は維持する。

条件統制の専用チェックカードは管理画面に表示しない。ただし、`condition_check_json` と関連する研究ログは、DB、管理API、詳細JSON、CSVで保持する。

管理画面には `/start` へ移動する「実験開始画面へ戻る」リンクを表示する。被験者一覧では各参加者を確認ダイアログ後に完全削除できる。削除中は対象ボタンを無効化し、成功後は参加者一覧、集計、全体ログを再取得する。削除対象の被験者別ログを表示中だった場合は、その表示を閉じる。
