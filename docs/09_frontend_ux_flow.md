# 09. Frontend UX Flow

## 基本方針

- 研究実験用UIとして、誤操作防止と記録の完全性を優先する
- 被験者には内部ラベルを見せない
- テストフェーズではヒント、チャット、即時正誤表示を出さない
- 入力途中の離脱に備えて回答保存状態を明確にする
- 管理画面では研究者がログと診断根拠を確認できるようにする

## Page List

### `/start`

被験者開始画面。

表示:

- 研究システムの簡単な説明
- 同意チェック
- 管理者用のgroup condition選択またはランダム割当ボタン
- 開始ボタン

注意:

- 個人名やメールアドレスは入力させない
- 実験条件名は管理者モードでのみ表示する

### `/pretest`

事前テスト。

表示:

- 1問ずつ表示
- 問題文
- 選択肢
- 次へ

禁止:

- 正誤表示
- ヒント
- 解説
- チャット欄
- 理由記述欄
- 自信度入力欄

送信時:

- 回答を即保存
- 最後の問題送信後 `/diagnosing` へ進む

### `/diagnosing`

AI診断中画面。

表示:

- 「回答を整理しています」のような自然な文言
- 内部Mラベルは表示しない
- app-server失敗時は管理者に知らせる導線を出す

成功後 `/learning-targets` へ進む。

### `/learning-targets`

学習対象一覧。

被験者にはM1〜M4を直接表示しない。

表示例:

```text
今回重点的に確認する内容

1. Attention: 人間の注意ではなく、モデル内部の重み付けとして確認します。
2. RAG: Fine-tuningとの違いを確認します。
```

表示:

- 最大4用語
- 各用語の自然言語の確認ポイント
- 開始ボタン

### `/learning/[termSlug]`

1用語の学習画面。

画面構成:

```text
┌──────────────────────────────┐
│ 対象用語・前回回答             │
├──────────────┬───────────────┤
│ AIミニ教材     │ AIチューター対話  │
├──────────────┴───────────────┤
│ 回答欄・自己説明欄             │
├──────────────────────────────┤
│ 次へ                           │
└──────────────────────────────┘
```

必須UI:

- 前回回答の表示
- AIからの確認ポイント
- チューター発話
- 学習者回答欄
- 自己説明欄
- 残りターン数
- 次の用語へ進むボタン

チャット制御ボタン:

- もう少し簡単に
- 例を見たい
- 反例を見たい
- 違いを比較したい
- 自分の説明を確認して

禁止入力への返答:

```text
この実験では、正解だけを提示することはできません。
代わりに、考えるための観点を1つ示します。
```

### `/retest`

即時再テスト。

- チャット不可
- ヒント不可
- 結果は即時表示しない
- 学習対象用語だけを出す
- 事前テストと同じ文面は使わない

完了後 `/l0-check` または2回目学習が必要なら `/learning-targets` へ進む。

### `/l0-check`

L0確認。

- ヒントなし
- 解説なし
- チャット欄なし
- 自由記述中心
- 理由記述必須
- 即時正誤表示なし

### `/transfer-test`

転移テスト。

- ヒントなし
- チャット欄なし
- 別文脈問題
- 理由記述必須
- 即時正誤表示なし

### `/survey/post`

主観評価。

入力:

- 分かりやすさ
- 使いやすさ
- ヒント量の適切さ
- 自信の変化
- 自由記述

### `/finish`

終了画面。

表示:

- 実験終了メッセージ
- 被験者ID
- 管理者へ知らせる案内

正答率や内部診断結果は表示しない。

### `/admin`

管理者画面。

表示:

- 被験者一覧
- 実験進捗
- 群条件
- 学習対象用語
- 誤概念タイプ分布
- AI診断失敗ログ
- Codex app-server接続状態
- CSV出力
- データ削除

管理者だけに表示してよいもの:

- M1〜M4
- L0〜L3
- recurrence_flag
- AI診断JSON
- diagnosis_confidence
- manual review flag

## UI文言変換

内部ラベルを被験者用に変換する。

| 内部 | 被験者向け表示例 |
|---|---|
| M1 | 概念を少し別の種類のものとして捉えている可能性があります |
| M2 | 似ている用語との違いを確認します |
| M3 | 言葉の表面ではなく、仕組みに注目して確認します |
| M4 | 別の場面でも同じ考え方を使えるか確認します |
| L3 | しっかり確認 |
| L2 | 観点を確認 |
| L1 | 自分で整理 |
| L0 | ヒントなし |

L0はテスト画面では「ヒントなし」と表示してよいが、研究説明として扱い、内部状態として強調しない。

## Validation

全回答フォーム:

- 選択式問題は選択必須
- 事前テストでは理由記述と自信度を要求しない
- 再テスト、L0、転移では理由記述は20文字未満でも保存するが、短すぎる警告を出してよい
- 二重送信を防ぐ
- 送信中はボタンをdisabledにする

## Accessibility

- キーボード操作可能
- フォームラベルを明示
- コントラスト確保
- 長文問題でレイアウト崩れしない

## Admin Safety

削除・手動修正には確認ダイアログを出す。

手動修正対象:

- is_correct
- diagnosed_status
- misconception_type
- diagnosis_confidence
- requires_manual_review

修正理由を必須にし、`audit_events` に保存する。
