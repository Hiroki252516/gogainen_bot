# 15. Security and Privacy

## 計画書の目標と未確定事項

参加者へ研究目的・手順・所要時間・AI利用・ログ保存・任意中止と不利益がないこと・利用方法・削除/撤回方法・問い合わせ先を説明して同意を得る。回答履歴等をAI処理のためCodex app-serverへ送信することを明記し、個人を特定する情報をAI入力に含めない。

具体的な保管期間・撤回の期限/受付手順・割付記録との照合方法は計画書だけから補わず、実験前に確認する。旧試用保護の409や管理用削除APIがあることを、参加者からの撤回手順が整備済みである証拠にしない。

新しいアンケートは [目標項目](12_evaluation_metrics.md#アンケートの目標) と現行10段階評価・4段階用語知識の保存を区別し、既存回答を新尺度へ変換しない。以下は現行の保存・アクセス仕様と注意事項である。2026-10-27のユーザー指定により管理パスワード認証を追加した。[計画書対応表](20_experiment_plan_alignment.md) を参照する。

## 個人情報

氏名・メールアドレスは収集しない。2026-11-11の実装では、登録画面から研究者が伝えた研究用コードを受け取り、研究DBとは分離した専用対応表へ保存する。これは同意文書との統合・研究倫理上の承認を意味しないため、文書と研究手続きを確認するまで実参加者の登録に使わない。研究データは参加者IDのみで管理する。

保存しない:

- 氏名
- メールアドレス
- 研究用コード（研究DB・AI入力・AIログ・通常の研究用CSV/XLSXには保存しない。分離対応表と専用管理CSVのみで扱う）
- 学籍番号（旧対応表の既存行は保全し、新規登録には使わない）
- 電話番号
- ChatGPT認証情報
- APIキー

## ChatGPT/Codex認証

- ChatGPT認証情報をDBに保存しない
- `~/.codex/auth.json` をアプリで直接読み取らない
- app-serverの認証状態は `account/read` で確認する
- logout API（`/api/admin/ai/logout`）を提供する。現行管理画面にはログアウトボタンを置いていない。今後導線を追加する場合は誤操作防止の確認を入れる

## 管理画面・管理APIのアクセス（現行MVP）

2026-10-27のユーザー指定により、管理画面を開く際に伏せ字のパスワード入力ポップアップを表示する。既定パスワードはabcで、READMEへ明記する。backendのADMIN_PASSWORDで変更でき、パスワードはfrontendのコード・localStorage・研究DB・AI入力へ保存しない。

全管理API（ログ・CSV・分離対応表・削除・AI接続と設定を含む）、POST /api/seed、管理用の評価再計算をbackend認証で保護する。認証前は管理画面の子コンポーネントを表示せず、管理データを取得しない。HttpOnly/SameSite=Strict Cookie、HTTPS時のSecure、管理書込みのOrigin照合、管理応答のno-storeを適用する。30分のセッションは単一backendプロセスのメモリだけに保存し、ロック・ログアウト・再起動で失効する。画面を離れる際にもログアウトを要求し、再入場時は再入力する。ロック操作では通信結果を待たず画面を隠す。通信失敗・タイムアウト時はサーバー側の解除を確認できないことを表示し、再試行の成功まで再入場を不可とする。通信断ではサーバー側のセッションが期限まで残り得るため、参加者へ端末を渡す前に再試行を成功させ、APIが401となることを確認する。

これは指定された共通パスワードによるローカル実験用の保護であり、個別の研究者アカウント・権限分離・多プロセス共有セッションは提供しない。READMEを読める人にもパスワードは分かる。ChatGPT/Codexログインや実験仕様版guardとは独立する。削除前の既存確認ダイアログも維持する。

**本実験開始前:** 実際の配布環境で未認証の管理画面・管理API・CSV・対応表取得が拒否されることを確認する。同意書の責任者・保存場所・保管期間等は引き続き未確定であり、この認証追加だけで収集開始可能とはしない。

## app-serverの公開範囲

- `127.0.0.1` のみにバインドする
- `0.0.0.0` で公開しない
- 可能なら capability token を使う
- 非ローカル公開はしない
- 現行Composeの既定はhost networkで、backendは`.env`の`CODEX_APP_SERVER_URL=ws://127.0.0.1:4500`を使う。bridgeネットワークを選ぶ場合だけ`host.docker.internal:4500`などへ上書きする

## 実験データ

保存する:

- 回答
- 回答時間
- backendの固定採点・分類
- AI教材・回答後解説
- 学習ログ
- 意味的な学習stageと固定教授方略
- AI call log、診断・学習ログ、再発イベント

新規のテスト・学習回答APIは複数選択と時刻情報を受け付け、理由記述・自由回答・回答時自信度は受け付けない。画面に入力欄がないだけでなく、現行の回答型で廃止フィールドを拒否する。過去の理由記述・回答時自信度・AI診断などは旧ログとして保持し、現在の任意入力とは扱わない。

アンケートの経験・知識などの自己評価は別の入力であり、この回答APIの制限では廃止しない。分類ログのconfidenceはbackendが固定採点結果へ設定する値であり、学習者の自信度やLLMが推定した診断確信度ではない。

仕様版26のinteraction_historyは同じ参加者・用語の採点済み問題/選択/全体正誤/時刻だけを両群のモデルへ渡す。内部ID・診断・教授メタデータを共通履歴から除き、AI教材/解説全文も含めない。実験群だけの診断追加と、監査用に保存する情報を区別する。仕様版1〜25の試用は進行・補修・削除・再計算せず、記録を閲覧専用に保持する。

保存しない:

- 個人名
- メールアドレス
- ChatGPTアクセストークン
- APIキー

## AI出力の注意

AIは教材と解説だけを生成し、固定採点・分類・状態・方略をAIに変更させない。教材の契約ID・指定方略・必須フィールド・本文証拠・章立て・禁止文字列はbackendで検査する。本文文字数は仕様版41で目標値だけを参考記録し、合否判定には使わない。事実的正しさや反駁の妥当性、言い換えによる正答漏えい、意味的な過去解説混入まで自動保証しない。入力分離・プロンプト指示・研究者の目視確認を区別する。詳細は [AI契約の検証範囲](10_ai_prompt_contracts.md#出力検証) を参照する。旧試用は読取り専用で回答や評価を更新しない。

手動修正（将来対応）:

- 修正前後を `audit_events` に保存
- 修正理由を必須にする
- CSVで手動修正済みか判別可能にする

## 削除機能（現行MVP）

現行版の参加者だけは管理画面の確認後にDELETEできる。旧試用は削除も409で拒否する。現行版の削除は所有レコードのみを対象とし、seedや他参加者の記録を消さない。

削除前に`delete_participant`の`AuditEvent`を保存し、参加者削除後もその監査記録を残す。削除は被験者1名単位であり、全参加者一括削除、全実験データ削除、CSV/export file削除のAPIはない。

参加者削除は、研究DBの関連データ削除と対応表削除待ち（`identity_mapping_cleanup=pending`）を先に同一commitし、その後に別SQLiteの学籍番号対応表・研究用コード対応表の行を削除する。成功後に監査状態を`complete`へ更新する。対応表DBの停止やプロセス強制終了で未完了になった場合、pending状態を起動時に再試行し、削除APIの再送でも完了できる。APIが503を返した場合は研究データの削除自体は確定済みで、両対応表の消去が保留中であるため、復旧後に同じ削除APIを再試行する。研究DB側commitが失敗した場合には対応表を削除しない。二つのDBをまたぐ原子的commitではなく、失敗状態を記録して再実行する補償可能な手順である。

## 診断結果の手動修正（将来対応）

現行管理画面では診断・AI call logを確認できるが、診断結果を編集するUIと修正内容の監査書き込みは未実装である。導入時は修正前後、修正理由、CSVでの判別方法を定義する。

## ローカル用途

このシステムは卒業研究用のローカル実験システムであり、インターネットに公開しない。

## ログ出力

アプリケーションログに出してよいもの:

- participant display_code
- API endpoint
- error_code
- latency

出してはいけないもの:

- ChatGPT token
- capability token
- raw auth response
- secret file pathの中身

## CSV取扱い

CSVは研究分析用データであり、回答テキストが含まれるため、研究者限定で取り扱い、外部公開しない。管理APIには上記の共通パスワード認証を適用するが、取得済みCSVの外部コピーは研究者が別途管理する。

CSV出力先:

- `exports/`
- gitignore対象

## セキュリティ上の実装禁止事項

- OpenAI APIキー入力欄
- 認証トークンのDB保存
- app-serverの外部公開
- 管理画面の削除APIを確認なしで実行
- 管理者認証・権限確認が未実装なのに、参加者からの管理機能へのアクセスを防止済みと説明すること
