# 15. Security and Privacy

## 計画書の目標と未確定事項

参加者へ研究目的・手順・所要時間・AI利用・ログ保存・任意中止と不利益がないこと・利用方法・削除/撤回方法・問い合わせ先を説明して同意を得る。回答履歴等をAI処理のためCodex app-serverへ送信することを明記し、個人を特定する情報をAI入力に含めない。

具体的な保管期間・撤回の期限/受付手順・割付記録との照合方法は計画書だけから補わず、実験前に確認する。旧試用保護の409や管理用削除APIがあることを、参加者からの撤回手順が整備済みである証拠にしない。

新しいアンケートは [目標項目](12_evaluation_metrics.md#アンケートの目標) と現行5段階の保存を区別し、既存回答を新尺度へ変換しない。以下は現行の保存・アクセス仕様と注意事項であり、今回セキュリティ機能を追加したわけではない。[計画書対応表](20_experiment_plan_alignment.md) を参照する。

## 個人情報

氏名・メールアドレスは収集しない。2026-10-21のユーザー承認により、同意画面で学籍番号を必須入力し、研究DBとは分離した対応表へ一時保存する。研究データは参加者IDのみで管理する。

保存しない:

- 氏名
- メールアドレス
- 学籍番号（研究DB・AI入力・AIログ・研究用CSVには保存しない。分離対応表のみで扱う）
- 電話番号
- ChatGPT認証情報
- APIキー

## ChatGPT/Codex認証

- ChatGPT認証情報をDBに保存しない
- `~/.codex/auth.json` をアプリで直接読み取らない
- app-serverの認証状態は `account/read` で確認する
- logout API（`/api/admin/ai/logout`）を提供する。現行管理画面にはログアウトボタンを置いていない。今後導線を追加する場合は誤操作防止の確認を入れる

## 管理画面・管理APIのアクセス（現行MVP）

対応表の表示・CSV取得・個別削除・全件削除も管理APIとして提供する。ユーザー指定により今回も認証は追加せず、削除前の確認ポップアップだけを追加した。これはアクセス制御ではなく、本実験前のアクセス対策は未解決のままである。実際の学籍番号を使う収集開始可能とは扱わない。

現行の管理画面・管理APIには管理者認証・権限確認がない。参加者画面にも管理画面リンクがあり、移動時の確認ダイアログは誤操作防止であってアクセス制御ではない。ChatGPT/CodexログインはAI呼び出し用であり、管理者の認証・認可の代わりにはならない。実験仕様版の書込みguardも旧試用の保護であり、管理者権限を判定する機能ではない。

ログ・CSVを「研究者限定で扱う」は運用方針であり、参加者や同じ端末からのアクセスをシステムが防止する保証ではない。ローカル実行、URLの非公開、確認ダイアログ、参加者向け出題APIからの正答情報除外だけでは、管理機能・生AIログへのアクセスを防げない。

**本実験開始前の未解決事項:** 参加者による管理画面・管理API・ログ・CSVの閲覧や管理操作を防ぐアクセス対策を決定し、実際に有効であることを確認する必要がある。この文書修正では認証機能を追加せず、対策済みとも扱わない。

## app-serverの公開範囲

- `127.0.0.1` のみにバインドする
- `0.0.0.0` で公開しない
- 可能なら capability token を使う
- 非ローカル公開はしない
- 現行Composeの既定はhost networkで、backendは`.env`の`CODEX_APP_SERVER_URL=ws://127.0.0.1:4500`を使う。bridgeネットワークを選ぶ場合だけ`host.docker.internal:4500`などへ上書きする

## 実験データ

保存する:

- 回答
- 回答時間
- backendの固定採点・分類
- AI教材・回答後解説
- 学習ログ
- 意味的な学習stageと固定教授方略
- AI call log、診断・学習ログ、再発イベント

新規のテスト・学習回答APIは複数選択と時刻情報を受け付け、理由記述・自由回答・回答時自信度は受け付けない。画面に入力欄がないだけでなく、現行の回答型で廃止フィールドを拒否する。過去の理由記述・回答時自信度・AI診断などは旧ログとして保持し、現在の任意入力とは扱わない。

アンケートの経験・知識などの自己評価は別の入力であり、この回答APIの制限では廃止しない。分類ログのconfidenceはbackendが固定採点結果へ設定する値であり、学習者の自信度やLLMが推定した診断確信度ではない。

仕様版24のinteraction_historyは同じ参加者・用語の採点済み問題/選択/全体正誤/時刻だけを両群のモデルへ渡す。内部ID・診断・教授メタデータを共通履歴から除き、AI教材/解説全文も含めない。実験群だけの診断追加と、監査用に保存する情報を区別する。仕様版1〜23の試用は進行・補修・削除・再計算せず、記録を閲覧専用に保持する。

保存しない:

- 個人名
- メールアドレス
- ChatGPTアクセストークン
- APIキー

## AI出力の注意

AIは教材と解説だけを生成し、固定採点・分類・状態・方略をAIに変更させない。教材の契約ID・指定方略・必須フィールド・本文証拠・章立て・文字数・禁止文字列はbackendで検査するが、事実的正しさや反駁の妥当性、言い換えによる正答漏えい、意味的な過去解説混入まで自動保証しない。入力分離・プロンプト指示・研究者の目視確認を区別する。詳細は [AI契約の検証範囲](10_ai_prompt_contracts.md#出力検証) を参照する。旧試用は読取り専用で回答や評価を更新しない。

手動修正（将来対応）:

- 修正前後を `audit_events` に保存
- 修正理由を必須にする
- CSVで手動修正済みか判別可能にする

## 削除機能（現行MVP）

現行版の参加者だけは管理画面の確認後にDELETEできる。旧試用は削除も409で拒否する。現行版の削除は所有レコードのみを対象とし、seedや他参加者の記録を消さない。

削除前に`delete_participant`の`AuditEvent`を保存し、参加者削除後もその監査記録を残す。削除は被験者1名単位であり、全参加者一括削除、全実験データ削除、CSV/export file削除のAPIはない。

参加者削除は、研究DBの関連データ削除と対応表削除待ち（`identity_mapping_cleanup=pending`）を先に同一commitし、その後に別SQLiteの対応行を削除する。成功後に監査状態を`complete`へ更新する。対応表DBの停止やプロセス強制終了で未完了になった場合、pending状態を起動時に再試行し、削除APIの再送でも完了できる。APIが503を返した場合は研究データの削除自体は確定済みで、対応表の消去が保留中であるため、復旧後に同じ削除APIを再試行する。研究DB側commitが失敗した場合には対応表を削除しない。二つのDBをまたぐ原子的commitではなく、失敗状態を記録して再実行する補償可能な手順である。

## 診断結果の手動修正（将来対応）

現行管理画面では診断・AI call logを確認できるが、診断結果を編集するUIと修正内容の監査書き込みは未実装である。導入時は修正前後、修正理由、CSVでの判別方法を定義する。

## ローカル用途

このシステムは卒業研究用のローカル実験システムであり、インターネットに公開しない。

## ログ出力

アプリケーションログに出してよいもの:

- participant display_code
- API endpoint
- error_code
- latency

出してはいけないもの:

- ChatGPT token
- capability token
- raw auth response
- secret file pathの中身

## CSV取扱い

CSVは研究分析用データであり、回答テキストが含まれるため、研究者限定で取り扱い、外部公開しない。この取扱い方針は管理APIへの認証・権限確認が実装済みであることを意味しない。

CSV出力先:

- `exports/`
- gitignore対象

## セキュリティ上の実装禁止事項

- OpenAI APIキー入力欄
- 認証トークンのDB保存
- app-serverの外部公開
- 管理画面の削除APIを確認なしで実行
- 管理者認証・権限確認が未実装なのに、参加者からの管理機能へのアクセスを防止済みと説明すること
