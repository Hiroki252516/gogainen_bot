# RAGを用語注釈へ追加（仕様版36）

> 本書の仕様版36節は辞書v4を導入した時点の採用記録である。現行仕様版54でも辞書v4を使用し、登録・抽出・snapshotの現行条件は[用語注釈仕様](24_learning_glossary.md)を参照する。仕様版53以下の保存済み注釈は当時のsnapshotを維持する。

## 適用

仕様版36 / `experiment-plan-2026-11-04-rag-glossary-v1`から、新規参加者に共通用語辞書v4を適用する。v3は履歴として不変で保持し、v4では辞書v1のRAG entryを定義・別表記・出典ごと追加する。仕様版35以下は閲覧専用とし、仕様版35のテスト結果は通常版`split-actions-v5`から復元する。

```yaml
id: rag
term: RAG（検索拡張生成）
aliases: [RAG, 検索拡張生成]
definition: 質問に関係する資料を外部から検索し、取り出した情報を使ってAIに回答を作らせる仕組みです。
sources: ["rag_agent_knowledge_base/sources/source_01.txt:43-45"]
```

辞書は`backend/app/seed/content/learning_glossary_v4.yml`。v1〜v3は履歴ファイルとして変更しない。ほかのv3項目、別表記、除外語、出典と抽出規則は維持する。v4は既存16語にRAGを加えた17語となる。

## 表示と抽出

テスト・教材・回答後解説で既存の注釈対象となっている表示本文から抽出する。確認問題本体・テスト結果画面は対象外。教材の「注釈欄のみ」では従来どおり辞書を教材生成入力に含めず、「教材内解説」ではv4を両群共通の意味参照として渡す。教材では使う用語だけを文脈に合わせて説明し、定義文を逐語転載しない。

抽出器のNFKC正規化とcase-foldにより`RAG`、`rag`、全角`ＲＡＧ`を同じ語として検出する。「検索拡張生成」も同じ`rag` entryへまとめる。英字略語は英数字・underscoreを語の境界として扱うため、`RAGged`や`my_RAG`の一部一致はしない。Markdownリンクは表示文字列を対象とし、リンク先URLだけに現れる語は抽出しない。既存の複合除外語による短い語のマスキングも維持する。

## 保存と互換性

未回答の表示内容はv4から導出し、回答時に既存形式のglossary snapshotへ保存する。回答済み再取得・冪等再送は保存snapshotを優先し、既存v1〜v3 snapshotは当時の辞書版・説明のまま返す。古い行へのsnapshot補完や、過去の教材・テスト・回答の書換えは行わない。

仕様版35の結果復元は`split-actions-v5`を使う。新規参加者のバンク・採点・設問表示は変更しない。DB構造、公開API形式、辞書snapshot形式、画面レイアウト、AIの群別方針は変更しない。

## 受入確認

- v3のファイルが不変で、v4がv3と一致し、RAG entryだけを追加したことを検査する。
- 表記ゆれ、全角、別表記、`RAGged`等の境界、Markdownリンク文字とURLを検査する。
- 既存snapshotの再表示、新規snapshotの保存、仕様版35のv5結果復元、仕様版36の登録を確認する。
- 自動テストは抽出・保存・版管理の契約を確認するものであり、定義の教育的妥当性や学習効果を実証しない。
