# 実験フロー

1. start → consentで参加コードA/Bを受け取り、新しい参加者を作成する。
2. pretestで3概念を回答し、固定採点する。結果確認画面で問題・選択内容・正誤を表示する。
3. 学習対象があればlearning_targetsから用語順に学習する。なければfinal_testへ進む。
4. 学習はAI教材＋固定確認問題。各用語最大3回答で、正解または3回の不正解後に次の対象へ進む。不正解の用語は未達のまま残る。
5. 全対象の学習後、retestで3概念を回答する。全問正解ならsurvey、そうでなければ結果確認後に未達用語の学習へ戻る。
6. final_testも結果確認を必ず表示し、全問正解ならsurvey、不正解があれば学習へ進む。final_test状態から採点を飛ばして学習を開始できない。
7. survey保存後にfinish。

再テストは受験1〜5回目で別variant、6回目以降はvariant5。final_testは事前全問正解者の最初の確認で、retest合格者へ重ねて出さない。回答中の正解・ヒントは表示しないが、送信後の結果確認は正誤を表示する。

学習ギブアップはretestへ進む。retest/final_testの実験ギブアップはsurveyへ進む。採点・ギブアップ・再送・先行生成は仕様版の確認後に実行する。

旧試用は `current-step` で `legacy_read_only` / `can_resume=false` を返す。画面の新規開始ボタンはブラウザの参加者・進行・保留送信情報だけを消し、startから同意を取り直す。DB記録は残す。
