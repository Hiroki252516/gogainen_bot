# Experiment Flow

## 対象と問題形式

新規セッションの対象は `llm_knowledge`、`multi_agent`、`memory_process` の3用語である。LangGraphおよび旧Transformer用語は新規フローから除外する。

各固定テスト問題は10択複数選択である。

- A〜C: 正解選択肢
- D〜F: M1選択肢
- G〜I: M3選択肢
- J: 「わからない」

A/B/Cの3つだけを選択した場合だけ正解とする。Jは単独選択の場合だけ有効であり、他の選択肢との同時選択は不正解である。不正解分類は `M3 > M1 > unknown` の順に決定する。

## フロー

1. `pretest`: 参加者向けには「テスト」と表示し、3用語を各1問出題する。正誤、ヒント、教材は表示しない。
2. 診断・学習対象選択: 正解済み用語を除き、誤答・unknownの用語を学習対象にする。
3. `learning`: 用語ごとに教材を生成し、確認問題を出題する。学習段階ごとに5バリエーションを持ち、6回目以降は5問目を再利用する。
4. `retest`: 各用語を `retest_v1`〜`retest_v4` で出題する。5回目以降は `retest_v4` を再利用する。テスト中はヒントと即時正解表示を行わない。
5. 再テストの3用語を各1問ずつ採点し、1問でも不正解または未回答がある場合、backendは `current_step=learning_targets` とする。不正解・未回答用語を優先度順に学習対象へ戻し、最初の用語の学習URLを返す。追加の学習・再テスト周回はクライアントまたは研究者が再導線を開始して行う。サーバーが3〜4を自動反復する機能は未実装である。
6. 再テストの3用語が各1件あり、すべて正解の場合だけ、backendは `current_step=survey` として追加の確認を省略する。採点対象が不足するなど満点を確認できない場合も `learning_targets` に留める。
7. `final_test` は初回テストで学習対象がない場合に使う内部フェーズで、参加者向けには「再テスト1」と表示する。3用語を各1問出題し、全問正解ならアンケートへ進み、不正解または未回答があれば学習対象を作って次の再テスト周回へ戻る。

学習セッション中の「学習をギブアップして再テストへ」は、回答を追加保存せず、開いている`TutorSession`を終了して`current_step=retest`へ進める。再テスト画面と再テスト結果確認画面の「実験をギブアップして終了」は、`current_step=finish`、`completed_at`、`completion_reason=give_up`を確定し、以後の問題取得・回答・採点を受け付けない。どちらの操作も`audit_events`へ参加者操作として記録する。

回答ログの `attempts.test_round` は、初回 `pretest` を `test`、最初の学習後確認を `retest_1`、次の確認を `retest_2` として保存する。`phase` は問題種別・既存API互換の内部値として残す。

L0確認・転移問題は互換・補助フェーズとして残すが、現行の主到達評価は `final_test` である。再テスト3用語が全問正解の場合だけ、再テスト満点を最終到達率相当として代用する。完全な転移評価、遅延再テスト、周回別の自動評価は将来対応である。DB上の旧問題・旧ログは削除しない。
