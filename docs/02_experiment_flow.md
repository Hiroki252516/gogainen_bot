# 実験フロー

## 目標と現行経路

計画書の手順は、事前テスト、必要な用語の学習、再テスト、未達用語の再学習、満点または中断後のアンケートという流れ。[6仮説](01_research_requirements.md) の測定上の回数・対象経路は別途定義が必要で、遷移が実装済みでも集計が確定したとはしない。

以下の遷移は維持する。Q09は最大3回答/3回不正解終了・測定0〜3不正解として確定した。内部final_testは初回再テスト・仮説6へ算入し、教材未表示者は仮説5の対象外とする。事前後のテストは学習前の`final_test`込み最大2回、事前込み最大3回とする。[採用判断](20_experiment_plan_alignment.md#要確認事項)を参照する。

## 現行実装

1. start → consentで参加コードA/Bを受け取り、新しい参加者を作成する。
2. pretestで3概念を回答し、固定採点する。結果確認画面で問題・選択内容・正誤を表示する。
3. 学習対象があればlearning_targetsから用語順に学習する。なければfinal_testへ進む。
4. 学習はAI教材＋固定確認問題。各用語最大3回答で、正解または3回の不正解後に次の対象へ進む。不正解の用語は未達のまま残る。
5. 全対象の学習後、retestで3概念を回答する。未回答を含む採点バッチも1回、全問未回答は採点しない。事前後1回目の未達は結果確認後に学習へ戻り、2回目の未達は未達のままsurveyへ進む。満点ならいつでもsurveyへ進む。
6. final_testも結果確認を必ず表示し、全問正解ならsurvey、不正解・未回答があれば学習後にretest_v2（再テスト2）へ進む。final_test状態から採点を飛ばして学習を開始できない。
7. survey保存後にfinish。

surveyは経験4有無・一般4/教材6の1〜10段階・必須自由記述。教材表示者のみ6項目を必須とし、未表示者は自動対象外。[画面仕様](09_frontend_ux_flow.md) と[評価定義](12_evaluation_metrics.md)を参照する。

事前後の採点回次に対応して全用語をretest_v1→retest_v2と選ぶ。用語別の回答件数を使わず、前回未回答でも次の問題へ進める。学習後回数retest_cycles_completedはfinal_testを含めないが、上限用post_pretest_tests_completedには採点済みfinal_testを加える。回答中の正解・ヒントは表示せず、送信後に正誤を表示する。

学習ギブアップはretestへ進む。retest/final_testの実験ギブアップはsurveyへ進む。採点・ギブアップ・再送・先行生成は仕様版の確認後に実行する。

学習確認の出題規則は両群共通で、unknownはenrichment、M1/M3はconceptual_change。同じ状態・回答・ターンなら同じ問題とvariantを使う。統制群の旧固定系列は使わない。

NULL・版1〜21・未対応版・旧protocol_idの記録はcurrent-stepでlegacy_read_only/can_resume=falseを返す。新規開始はブラウザの参加者・進行・保留送信だけを消し、同意を取り直して新規ID・版22・現行protocol_idを保存する。旧DB記録を残す。
