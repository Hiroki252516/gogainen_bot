新規参加者は仕様版51 / `experiment-plan-2026-11-12-posttest-material-amount-wording-v1`を使う。登録時snapshotされた問題モード・テスト進行・採点・結果表示を仕様版50から維持し、事後アンケート`posttest-5point-v3`の教材量設問文を「教材の量はどの程度でしたか」に更新する。事前アンケート理解度質問文、4用語版の表記・問題バンクv2は仕様版50で導入済み。標準2モードは`presurvey-baseline-v4`、4用語版は`presurvey-four-topic-baseline-v3`と`split-actions-four-topic-v2`を使う。事後はシステム評価2項目・教材評価6項目で、教材未閲覧時は教材回答をnullで保存する。結果・回答の保全、問題モード別集計、事前満点の早期終了条件は変えない。H5は教材の中核4項目の数値平均で、難易度と教材量は別の回答分布として扱う。仕様版50の先行protocolと仕様版49以下は当時の回答・問題を保ち、読み取り専用で扱う。[事前アンケート](49_presurvey_baseline.md)、[4用語版](51_four_topic_foundation_mode.md)、[事後アンケート](52_posttest_five_point_evaluation.md)、[評価指標](12_evaluation_metrics.md)。

## 仕様版48のフロー（履歴）

現行の新規参加者は、仕様版48で導入したモード別事前アンケートの条件を引き継ぎ、同意後に事前アンケート、事前テストへ進む。事前アンケートでは6用語の見聞き経験を必須取得し、「ある」の場合だけ理解度を必須表示する。AI利用頻度は直近30日の日数、使いこなしは3行動について取得する。回答保存後に事前テストへ進み、未完了のテスト開始は拒否する。事前テスト未達なら従来どおり誤答用語だけを学習する。事前テスト満点なら学習・内部`final_test`・再テストを行わず事後アンケートへ進む。結果表示ONでは結果確認後に、OFFでは結果確認を省いて直接surveyへ遷移する。直接URL・再読み込みも保存済みの`current_step`と表示snapshotに従う。3つの問題モード、登録時snapshot、各モードの問題・採点・学習確認は維持する。4用語版の事前未達経路では再テスト1後の学習・再テスト2までの既存固定フローを維持し、再テスト2後はsurveyへ進む。事前満点者は`pretest_perfect_early_exit`として別集計し、H1/H2/H6の適用分母から外す。仕様版49以下は閲覧専用で既存記録を変更しない。[事前アンケート](49_presurvey_baseline.md)、[4用語版](51_four_topic_foundation_mode.md)、[評価指標](12_evaluation_metrics.md)。

仕様版46では既定値を4用語版に統一し、事前満点でも学習する固定2回フローを適用した。仕様版47で事前満点時のみ早期終了へ変更した。

## 目標と現行経路

計画書の手順は、事前テスト、必要な用語の学習、再テスト、未達用語の再学習、満点または中断後のアンケートという流れ。6仮説の測定上の回数・対象経路は[01](01_research_requirements.md)と[12](12_evaluation_metrics.md)に定め、画面表示の変更で評価式は変更しない。

仕様版48で導入した事前アンケートと4用語版の条件は、それぞれ[事前アンケート](49_presurvey_baseline.md)と[4用語版フロー](51_four_topic_foundation_mode.md)を参照する。仕様版50の統合protocolでは理解度質問の表現と4用語版の用語・問題バンクを更新し、仕様版51では事後アンケートの教材量設問文だけを更新した。その他の進行条件は維持する。事前満点者はsurveyへ直行または結果確認後にsurveyへ進み、独立した早期終了経路として記録する。

仕様版42では新規登録・出題・学習・集計は通常版だけを扱い、問題バンクの切替経路はなかった。旧条件の保存データ削除は通常の起動・seedから分離し、[専用削除手順](../backend/scripts/purge_easy_mode_data.py)で明示実行する。

## 仕様版42の履歴フロー

1. start → consentで参加コードA/Bを受け取り、新しい参加者を作成する。
2. presurveyで用語事前知識6項目と普段のAI利用2項目へ回答し、必須8項目を保存してからpretestへ進む。未回答のまま事前テストは開始できない。
3. pretestで各用語の設問1だけ（計3問）へ回答する。各回答後に本人の選択と正誤を確認し、3問完了後に固定採点する。テスト全体の結果画面は表示しない。
4. 学習対象があればlearning_targetsから用語順に学習する。学習対象がなければ内部final_testへ進む。
5. 学習はAI教材＋固定確認問題。1用語・1セッションあたりの回答上限は既存仕様に従う。正解または上限到達後に次の対象へ進み、不正解の用語は未達のまま残る。
6. 全対象の学習後、retestで各用語の設問1だけ（計3問）へ回答し、各回答後に本人の選択と正誤を確認する。採点済みバッチは未回答を含めて1回とし、全問未回答は採点しない。初回未達は既存の再学習経路へ進み、最終回未達は未達のままsurveyへ進む。満点ならsurveyへ進む。
7. 事前テストで満点だった参加者は内部final_testへ進み、各用語の設問1だけ（計3問）へ回答後に本人の選択と正誤を確認する。採点結果に応じ、満点ならsurvey、不正解・未回答があれば既存の学習後retest_v2へ進む。
8. survey（事後アンケート）保存後にfinish。

事前アンケートはphase=presurvey、事後アンケートはphase=posttestで別々に記録する。事前はモード別の版付きで経験・条件付き理解度・AI利用回答を保存する。事後はシステム評価2項目・教材評価6項目（表示者のみ必須）・任意自由記述とし、仮説5はposttestだけを参照する。[画面仕様](09_frontend_ux_flow.md)、[評価定義](12_evaluation_metrics.md)、[保存契約](49_presurvey_baseline.md)を参照する。

事前後の問題variantは採点回次に対応して全用語共通に選ぶ。用語別の回答件数から回次を推測しない。学習後回数retest_cycles_completedはfinal_testを含めず、上限用のpost_pretest_tests_completedには採点済みfinal_testを加える。テスト回答中はチャット・ヒント・即時正解を表示しない。既存結果画面では従来どおり正誤を表示する。

学習ギブアップはretestへ進む。retest/final_testの実験ギブアップはsurveyへ進む。採点・ギブアップ・再送・先行生成は仕様版の確認後に実行する。学習確認の出題規則は両群共通で、unknownはenrichment、M1/M3はconceptual_change。同じ状態・回答・ターンなら同じ問題とvariantを使う。

仕様版42採用時には、仕様版41以下、旧protocol_id、NULL・未対応版の記録を閲覧専用で保全していた。新規開始は同意を取り直して新しいIDを作成した。当時の参加者には仕様版42を保存し、教材内解説では辞書v4を意味参照として生成入力に含め、本文では逐語転載せず文脈に合わせて言い換えた。本文は800文字程度を目安にし、文字数の上下限による合否判定や長さだけを理由にした再生成を行わなかった。教材の右側注釈欄は表示せず、統制群には群別の自然言語方略指示を送らず、提案群だけに診断・教授指示を追加した。旧版の保存済み教材・注釈snapshot・監査記録は変更しない。[事前アンケート](49_presurvey_baseline.md)、[教材モード](41_learning_glossary_material_mode.md)、[文字数目標](42_learning_glossary_material_length.md)、[辞書と言い換え](43_glossary_definition_paraphrase.md)、[PRETEST履歴](44_pretest_content_revision.md)、[RAG注釈](49_rag_glossary.md)。通常版ペア確認の契約は[40](40_question_pair_answer_review.md)に記録する。
