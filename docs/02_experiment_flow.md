# 実験フロー

## 目標と現行経路

計画書の手順は、事前テスト、必要な用語の学習、再テスト、未達用語の再学習、満点または中断後のアンケートという流れ。[6仮説](01_research_requirements.md) の測定上の回数・対象経路は別途定義が必要で、遷移が実装済みでも集計が確定したとはしない。

以下の遷移は維持する。Q09は最大3回答/3回不正解終了・測定0〜3不正解として確定した。内部final_testは初回再テスト・仮説6へ算入し、教材未表示者は仮説5の対象外とする。別途、学習後の`retest`は最大3回とし、学習前の`final_test`はこの上限に含めない。[採用判断](20_experiment_plan_alignment.md#要確認事項)を参照する。

## 現行実装

1. start → consentで参加コードA/Bを受け取り、新しい参加者を作成する。
2. pretestで3概念を回答し、固定採点する。結果確認画面で問題・選択内容・正誤を表示する。
3. 学習対象があればlearning_targetsから用語順に学習する。なければfinal_testへ進む。
4. 学習はAI教材＋固定確認問題。各用語最大3回答で、正解または3回の不正解後に次の対象へ進む。不正解の用語は未達のまま残る。
5. 全対象の学習後、retestで3概念を回答する。採点したretestを1回と数え、未回答項目があっても1回である。満点ならsurvey、未達なら1・2回目は結果確認後に未達用語の学習へ戻る。3回目の未達は未達記録を保ったままsurveyへ進み、追加の学習・再テストは行わない。
6. final_testも結果確認を必ず表示し、全問正解ならsurvey、不正解があれば学習へ進む。final_test状態から採点を飛ばして学習を開始できない。
7. survey保存後にfinish。

surveyは経験4有無・一般4/教材6の1〜10段階・必須自由記述。教材表示者のみ6項目を必須とし、未表示者は自動対象外。[画面仕様](09_frontend_ux_flow.md) と[評価定義](12_evaluation_metrics.md)を参照する。

学習後のretestは最大3回で、variant1〜3を使用する。3回目の未達後はsurveyへ進むため、通常経路でvariant4・5を使わない。`final_test`は事前全問正解者に対する学習前の確認であり、学習後retestの上限カウンターには含めない。回答中の正解・ヒントは表示しないが、送信後の結果確認は正誤を表示する。

学習ギブアップはretestへ進む。retest/final_testの実験ギブアップはsurveyへ進む。採点・ギブアップ・再送・先行生成は仕様版の確認後に実行する。

学習確認の出題規則は両群共通で、unknownはenrichment、M1/M3はconceptual_change。同じ状態・回答・ターンなら同じ問題とvariantを使う。統制群の旧固定系列は使わない。

NULL・版1〜3・未対応版・旧protocol_idの記録はcurrent-stepでlegacy_read_only/can_resume=falseを返す。新規開始はブラウザの参加者・進行・保留送信だけを消し、同意を取り直して新規ID・版4・現行protocol_idを保存する。旧DB記録を残す。
