# 通常版テストの設問分割（仕様版27）

## 採用内容

通常版だけを、1用語につき2つの4択単一選択設問へ変更する。3用語で6設問、各設問1点、6問正解を満点とする。設問3はYAMLに保持するがDBへactive問題として登録せず、表示・採点・学習対象に含めない。通常版のバンク識別子はsplit-actions-v1。旧scenario-actions-v9の本文と既存行は変更せず、旧仕様版26以下を閲覧専用にする。

新規参加者の仕様版は27、protocolはexperiment-plan-2026-10-29-split-tests-v1。易しい版は従来の3問・10択のまま、通常版とは分離して集計する。テスト回数は事前込み最大3回を維持する。事前満点時の内部final_testも再テスト1を使用する。

## テスト画面と時間計測（issue-208）

新規の通常版参加者は、用語ごとに2設問を同じページへ表示する（3ページ）。事前テスト、再テスト1/2、内部final_testで共通とする。両設問を個別に回答し、両方の回答がそろった場合だけ次のページへ進む。共通場面は本文の境界と完全一致を確認できる場合だけ一度表示し、それ以外は元の本文を欠落なく表示する。設問3は引き続き出題・採点しない。問題本文、選択肢、採点、学習対象、回数上限は変更しない。

新規参加者には`Participant.test_page_mode`を保存し、通常版は`per_term`、易しい版は`per_question`とする。既存参加者のNULLは補完せず、従来の設問ごとの表示・計測として扱う。画面・計測の変更は新規参加者だけに適用し、実験仕様版27とprotocolは変更しない。表示・回答時間の単位が異なる条件として研究ログに残す。

通常版はページを表示してから次へ/完了を押すまでの時間を用語ページ単位で計測する。2問を`POST /api/attempts/term-page`へ同一冪等キーでまとめて送信し、同一トランザクションで保存する。通信再試行は固定済み本文・時刻を再利用する。新形式の`Attempt.response_time_sec`はNULLとし、両回答のnullableな`test_page_timing_json`には同じpage_id・計測版・経過秒を保存する。既存回答を別の選択で上書きしない。テスト合計時間はpage_idごとに一度加算し、旧形式の回答は従来の設問単位時間を使う。管理ログ・回答履歴CSVでは表示方式と時間単位を識別し、統合ログCSVの固定列は維持する。

## 学習と保存

直前の採点済みテストの不正解設問だけを用語ごとにまとめる。両群に同じlearning_scopeを渡し、診断・訂正情報・教授方針は実験群だけに追加する。M1/M3が混在した場合はM3を主方針にしつつ両誤答を扱う。unknownが1つでもあればunknownを優先し、その用語の誤答本文・回答履歴を教材入力から除外して、対象の基礎を説明する。

確認問題は対象の各設問を同じ本文と4択で再出題する。用語内の全対象設問に1つずつ回答した後で採点・解説し、正誤にかかわらず次へ進める。各設問の結果はgrading_json.question_results、出題と内部採点情報はpractice_question_json.source_specに保存する。参加者向けAPIへsource_specや採点情報を公開しない。保存済みの表示順を優先する。設問ごとの回答時間はテストに保存し、確認問題の回答時間は用語内のまとめ回答単位とする。

複数の確認設問を同じ画面に表示する場合、保存本文の共通場面説明が完全一致し、空行と「設問1：」「設問2：」の境界を特定できるときは、フロントエンドで場面説明を一度だけ表示する。設問本文・snapshot・回答・採点データは変換・更新しない。単問、場面不一致、境界不明では元の本文をそのまま表示する。

確認回答の受け付け前に、保存済みsource_specの問題・4択・判定・表示snapshotの整合性を検査する。欠落・破損時は503（split_confirmation_snapshot_unavailable）で停止し、現行バンクでの補完、採点、AI呼び出し、回答・学習状態の更新を行わない。参照先の問題が欠落した場合や、variant_keyがpretest_v1/retest_v1/retest_v2の設問1・2として解釈できない場合も503（split_question_unavailable）とする。訂正情報案の欠落はsplit_correction_unavailableで明示する。これらは保存情報の不整合であり、参加者の誤答として扱わない。

学習対象を選ぶ際は、同じ用語の採点済みテスト回答について、保存されたtest_roundと参照先の設問版の対応も検査する。欠落・空値・不一致は503（split_test_round_unavailable）で停止し、異なる回次の誤答を混在させない。内部final_testはretest_v1に限る。attempt_indexは問題ごとの回答番号であり、再テスト1・2のどちらも1になり得るため、欠落回次の推定には使用しない。通常版の回次は起動時にも補完・書き換えず、易しい版の従来の補修だけを維持する。

新しい通常版はselection_mode=single、確認問題はgrouped_singleとquestions配列を使用する。解答は既存のselected_option_idsで送信し、各設問について必ず1つ選ばせる。採点APIは6設問分の回答が不足する場合に拒否する。デバッグ配置は正解・M1・M3・unknown、ランダム配置は先頭3択を並べ替えunknownをDへ固定する。

訂正情報はsplit_assessment.CORRECTION_DRAFTSに研究者確認用の案を置く。分類・正答・訂正内容の妥当性や難易度は機械検査で実証したとは扱わない。共通入力のlearning_scopeを追加したため生成契約版をtutoring-teaching-contract-v8-split-scopeとする。文字数と本文証拠の検査は維持する。

MockのM1/M3教材では、learning_scopeがある場合、pretest_targetsの非null値がリストであることと、各要素が非空文字列のclaim_id・observed_claimを持つ辞書であることを本文生成前に検査する。不正な項目を黙って除外せずValueErrorとする。統制群とunknownでは従来どおり診断対象を教材に使わない。実AIの教授指示・生成契約は変更しない。
