# 通常版PRETEST選択肢文面の改訂（仕様版33）

## 適用版と履歴

仕様版33 / `experiment-plan-2026-11-01-pretest-content-revision-v2`の新規参加者から、通常版テストバンク`split-actions-v3`を適用する。仕様版32以下は閲覧専用とし、既存の問題・回答・snapshot・評価を変更しない。版管理は仕様版27〜31を`split-actions-v1`、仕様版32を`split-actions-v2`、仕様版33を`split-actions-v3`とする。

仕様版32の改訂内容・原本は[44](44_pretest_content_revision.md)に保持する。v3はv2を基に、PRETESTの指定選択肢本文を更新し、バンクのstatusを`active_standard_split_v3`にする。選択肢の役割・ラベル・順序、問題場面、設問形式、正答、設問3のデータ、6設問形式、採点方法は維持する。v2と比較した本文差分は以下の8か所。

## 変更内容

### LLMに知識を与える方法

- 設問1の正解Aを、製品操作方法の質問を受け、対象製品の最新取扱説明書から操作手順・注意点を検索し、該当箇所を質問と一緒にAIへ渡す仕組みとして具体化する。
- 設問2の正解Aを、回答の項目と順序をプロンプトに明記し、指示文を質問とともに毎回AIへ渡す方法として具体化する。

### マルチエージェント

- 設問1の正解Aを、蔵書を調べるAIと貸出条件を調べるAIに異なる仕事を設定する説明へ具体化する。
- 設問2の正解Aは「蔵書担当の調査結果を利用条件の確認担当へ渡し、貸出可能な候補を絞り込ませる。」を維持する。

### 記憶プロセス

- 設問1のM1（表示ラベルB）は、会話全文を利用者別に保存すれば必要情報を自動的に使えるとして検索・受け渡しを設けない誤答を維持する。
- 設問1のM3（表示ラベルC）を、質問と回答の例を使う追加訓練を利用者別の希望保存・検索と同じ仕組みとして扱う誤答へ変更する。希望変更後の古い記録を残す誤答はこの設問から外す。
- 設問2の正解Aを、利用者別の古い希望を確認して新しい希望へ更新し、次回は更新記録を使う説明へ具体化する。
- 設問2のM1（表示ラベルB）は、新しい希望をAIに伝えるだけで保存記録も更新されると考え、記録更新を設けない誤答を維持する。
- 設問2のM3（表示ラベルC）は、全利用者共通の指示文を変えることを利用者別の記憶と同じ仕組みとして扱う誤答を維持する。

## 維持する動作

- RETEST1、RETEST2、内部`final_test`の設問・選択肢は仕様版32のv2と同一とする。
- 誤答したPRETEST設問を学習確認で再提示する場合は、回答時に保存した問題本文・選択肢snapshotを再利用する。seed後に旧問題を更新・削除しない。
- 既存の採点、回答保存、結果表示、API、DB構造は変更しない。
- 仕様版32以下の参加者は閲覧専用とする。過去の回答履歴は保存時に紐づく問題IDとsnapshotで参照する。

## 受入検証

- v1・v2のファイルを変更せず、v3のstatusおよび本文差分が上記の範囲であることを比較する。
- RETEST1/2がv2と一致し、選択肢の分類・ラベル・順序・正答が維持されることを確認する。
- 隔離DBで仕様版32のv2問題と仕様版33のv3問題が別construct keyで保存され、旧参加者・Attempt・snapshotがseed再実行後も保持されることを確認する。
- 仕様版33の学習確認では保存済みPRETEST snapshotがライブバンクの再取得より優先されることを確認する。
- 受入結果と実行環境は[14](14_testing_acceptance.md)に記録する。自動比較は選択肢の研究的妥当性、読みやすさ、難易度同等性、学習効果を実証するものではない。
