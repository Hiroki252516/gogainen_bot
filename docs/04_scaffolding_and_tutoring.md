# 現行の教材教授

文書名はリンク互換のため維持するが、段階的な支援量の計算・更新は行わない。

M1は誤った考え、正しい考え、反例、誤りの理由を含める。M3は誤カテゴリー、正カテゴリー、境界基準、近いカテゴリーとの比較を含める。unknownは定義、構成要素、役割、判断基準、正例、非例を含める。これらは必須の内容であり、見出し名・項目数・記述順序を指定するものではない。

proposed教材は上記の `mandatory_elements` と `teaching_contract` を必須にする。教材内の別事例への適用確認 `transfer_check` は必須であり、独立したテストやAI採点タスクではない。

全群の教材はMarkdown記号を含む600〜800文字、700文字前後。controlは定義・仕組み・具体例・注意点を含む一般説明であり、共通のinteraction_historyを利用し、回答から自然に誤りを訂正してよい。明示的な診断・タイプ別教授方針はproposedだけに追加する。

両群とも冒頭を `## 用語名` とし、少なくとも1つの非空 `###` セクションを作る。小見出しの文言・数・順序・まとめ方はAIが決める。要点・具体例・注意点など従来の見出しも、AIが自然に選んだ場合は許容する。複数の必須要素を1つの節にまとめてもよい。画面の教材/問題ラベルと回答後解説の見出しは変更しない。

mandatory_elementsとteaching_contractの証拠文は実際の節本文から正確にコピーさせる。見出しだけ、JSONだけの証拠は拒否する。見出しの先頭文やキーワードを含む任意の行で証拠を自動補正せず、不一致は同backendへ再生成させる。生成された見出しの表示順・節数・証拠配置・検証結果を既存のAIログとTutorTurn JSONへ保存する。

教授方略は `strategy_for` でbackendが固定し、出力Schemaのenumは当該方略1つのみ。別方略、欠落・不一致、安全性・文字数違反は初回＋最大2回の再生成で検証する。失敗は503にし、Mockへ切り替えない。

ここでの検証は契約・本文証拠・構造・文字数・禁止文字列の機械検査である。反駁や対比例が意味的に妥当か、訂正説明が事実として正しいかまでは自動保証しない。教授要件を満たすよう指示することと、生成内容の意味を検査することは区別し、研究者が目視確認する。[AI契約](10_ai_prompt_contracts.md#出力検証) に検査の範囲と限界を記載する。

`learning_stage` はunknownの `enrichment` とM1/M3の `conceptual_change`、回答後の `final_feedback` を示す。出題制御は両群共通の `shared-diagnosis-route-v1`。controlのモデルへ段階を送らず、proposedの診断介入だけが段階を利用する。

直前の確認問題のAI解説・振り返り全文は次の教材生成入力に含めず、転載しないようプロンプトでも指示する。過去の問題・回答の自動prefix追記も行わない。履歴に観察記録を渡すことと、フィードバックを再表示することを分離する。ただし、生成文が意味的に過去解説と似ているかを自動判定する機能はない。
