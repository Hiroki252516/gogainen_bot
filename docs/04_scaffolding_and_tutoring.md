# Scaffolding and Tutoring

学習セッションでは、提案群だけが誤答タイプ・学習段階・履歴に応じて教材生成の焦点を変える。固定問題の判定はbackendが行い、AIは用語情報と共通RAGをもとに教材本文を生成する。固定問題、選択肢、正答は教材生成AIへ渡さない。

現行の固定10択問題では、M1・M3・unknownを選択肢から決定論的に判定する。M2・M4の定義と教材方略は実行時taxonomyとしてAI payloadへ渡されるが、現行固定問題の状態としては直接割り当てず、将来の診断問題設計用に保持する。

| learning_stage | 表示上の役割 | 支援の焦点 |
| --- | --- | --- |
| `enrichment` | 豊富化 | unknown・知識不足に対し、用語、構成要素、基本例を補う |
| `conceptual_change` | 概念変化 | M1〜M4に応じ、信念、モデル、カテゴリー、スキーマの誤りを修正する。現行の固定問題が直接割り当てるのはM1/M3で、M2/M4はtaxonomy・将来設計として保持する |
| `final_feedback` | 教材フィードバック | 確認問題後の短い要点整理 |

`L3`/`L2`は`scaffolding_level`に保存する内部互換・ログ値である。現行の参加者向け学習段階は上表の意味的な`learning_stage`で決まり、L3の学習を終えてL2へ進む固定の二段階フローは実装していない。

## Mタイプ別の教授方略

- M1: `誤った考え`、`正しい考え`、`反例`、`誤りの理由`を教材本文へこの順で必ず含める。
- M2: 個別事実の訂正だけで終わらせず、モデルを支える中核前提を複数確認し、因果・構成関係を再構成する。
- M3: `誤カテゴリー`、`正カテゴリー`、`境界基準`、`近いカテゴリーとの比較`を教材本文へこの順で必ず含める。
- M4: 欠けている概念ノードや関係を補い、新しいスキーマを例・関係・適用場面とともに構築する。
- unknown: 誤概念とは断定せず、定義、構成要素、役割、判断基準、正例、非例を教材本文へ必ず含める。

現行MVPではM1、M3、unknownについて、`mandatory_elements` の各証拠文が教材本文に実際に含まれるかをbackendが検証する。欠落時は同じAIバックエンドで再生成し、Mockには切り替えない。

M1、M3、unknownの教材は、共通の「要点・具体例・注意点」構造を使わず、上記の必須教授要素をそのままMarkdown見出しの順序として使う。M2・M4および統制群など、必須教授要素の対象外は共通教材構造を使う。

## control / proposed

両群で用語・構成要素と、学習段階や個人診断を使わず用語条件だけで取得した同一RAGを共有する。固定問題、選択肢、正答、参加者ID、群名は教材生成promptへ含めない。固定問題の表示・採点はYAML/backendが担う。

- `control`: 通常のAIチューターとして、共通の用語情報とRAGから一般的な定義、仕組み、例、注意点を説明する。回答・診断・学習段階・履歴は生成入力へ含めない。一般的な誤解を正確に説明・訂正することは妨げない。
- `proposed`: 学習ログ、誤概念タイプ、足場掛けレベル、過去応答と研究者確認済みの事前テストtargetを追加し、Mタイプ別方略を生成する。直前の確認問題の解説・振り返りは次教材へ含めない。
- 両群の教材本文は450〜850字程度を共通の目安とし、文字数・段落数・箇条書き数を記録する。範囲外でも文字数だけを理由に再生成しない。

被験者向け本文にはMラベル、内部戦略、研究根拠を表示しない。テストフェーズでは教材、ヒント、即時正解を表示しない。
