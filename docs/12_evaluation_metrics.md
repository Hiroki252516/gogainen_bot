# 六つの仮説の評価指標

## 仕様版47：事前満点の早期終了を分離

仕様版47 / `experiment-plan-2026-11-10-pretest-perfect-early-exit-v1`では、事前テスト全問正解者は学習・再テストに進まない。この経路を`pretest_perfect_early_exit`として通常の学習・再テスト経路と分け、`six-hypotheses-v7-pretest-perfect-exit`で記録する。集計では群ごとの登録者総数と事前満点早期終了者数を別に示す。

事前満点者はH1・H2・H6の対象外とする。値を0や未達として補完せず、各指標の`not_applicable_count`を数え、`eligible_count = participant_count - not_applicable_count`を適用分母として表示する。H1/H2/H6の`missing_count`から対象外者を除く。H6の到達率は早期終了者を含む全登録者ではなく、適用可能者の満点到達数÷適用分母である。ルート別集計と`pretest_perfect_early_exit_count`により、早期終了人数は別途確認できる。

H3〜H5は既存の対象外・欠測規則を維持する。例えば、学習教材を表示しない早期終了者はH3/H5の値を補完せず、既存ルールに従い対象外または欠測とする。H4も事前M1/M3がない場合の従来の対象外規則を維持する。再テスト回次のgain/recurrenceでは早期終了者を対象外として、適用分母・対象外数・欠測数を区別する。3問題モード間の集計分離、各仮説のその他の式、H3〜H5の扱いは変更しない。変更は測定特性や研究上の承認を示すものではない。

## 仕様版46：4用語版の既定値と固定2回フロー（履歴）

仕様版46では未設定時の既定を4用語版にし、事前満点でも学習を続けて再テスト2まで実施した。指標版は`six-hypotheses-v6-four-topic-mode`。H2は最初に満点となった再テストまでに表示した学習セッション数、H6は再テスト1または2のいずれかで満点に到達したか、H1は事前テストと再テスト1の比較だった。仕様版47はその後の新規参加者にのみ適用され、仕様版46以下の指標・記録を付け替えない。[4用語版](51_four_topic_foundation_mode.md)。

## 仕様版44・45：問題モード集計（履歴）

仕様版44で対象モードを`application`、`basic_understanding`、`four_topic_fundamentals`へ拡張した。仕様版45では既定モードの変更と4用語版の固定2回フローを別protocolで導入した。参加者値、群集計、群間差、CSV/XLSXをモードごとに算出し、異なる問題モードの結果は合算しない。4用語版では対象4用語の完答・正答率・満点判定を分母4で扱う。既存6仮説の意味・式・欠測規則は維持し、教材評価は引き続き事後アンケートだけを参照する。指標版は`six-hypotheses-v6-four-topic-mode`。モード間の難易度・測定特性・回次間同等性は未検証。[4用語版](51_four_topic_foundation_mode.md)。

## 対象と版（現行仕様版47）

新規参加者は実験仕様版47 / `experiment-plan-2026-11-10-pretest-perfect-early-exit-v1`を対象とし、仮説集計・群比較・CSV/XLSXは`test_content_mode`ごとに分ける。仕様版46以下、NULL・未対応版、旧protocolは閲覧・保存記録出力に限り、新指標へ付け替えたり再計算したりしない。

現行指標版は`six-hypotheses-v7-pretest-perfect-exit`。事前テストで全問正解した参加者は`pretest_perfect_early_exit`として分け、H1・H2・H6を対象外にする。実験版ごとの問題数は、現行版・基礎理解版が3問、4用語版が4問。参加者ごとのテスト完答は、当該モードの期待問題が重複なくそろい、全て採点済みであることとする。部分回答や未採点を0点・満点としない。

事前後のテスト機会は最大2採点バッチで、内部`final_test`が使われる履歴経路では初回再テストとして数える。未回答を含む採点バッチも1回、全問未回答の採点は拒否する。再テスト2で未達なら未達のまま残す。早期終了、学習・再テスト経路、欠測を区別し、旧版の指標を再計算しない。

## 指標と集計

| 仮説 | 参加者の値 | 対象外・欠測等 |
| --- | --- | --- |
| 1 | 100×（初回再テスト正答率−事前正答率）、単位は百分率ポイント | 事前満点早期終了者は対象外。その他は両方の完答者のみ。各回の伸びも参考表示 |
| 2 | 最初の再テスト満点までに教材を表示した用語別セッションの累計 | 事前満点早期終了者は対象外。到達者の平均/中央値と未達者の観測回数を分離。学習なし到達は0回として別掲 |
| 3 | 各セッションの不正解数0〜3を用語内で平均し、回答のある用語間で平均 | 回答済み・固定採点済みターンのみ。未回答を0回としない。途中セッションも観測済み回答だけを数え、終了状況を保存 |
| 4 | 初回再テストで事前と同タイプだった用語数÷事前M1/M3用語数 | 両テスト完答者のみ。分母0は対象外。unknownへの変化は非再選択 |
| 5 | 教材評価6項目それぞれ、および6項目の算術平均 | posttest phaseのみ。教材表示者のみ。アンケート欠測は補完せず、未閲覧者は対象外 |
| 6 | 参加者ごとの再テスト満点到達有無（1/0） | 事前満点早期終了者は対象外。群の割合は到達人数÷適用対象人数。中断・再テスト未受験は未到達。アンケート完了とは独立 |

群別に登録者数、事前満点早期終了者数、平均、中央値、率、欠測・対象外を表示する。H1/H2/H6には`eligible_count = participant_count - not_applicable_count`を併記し、群間差は適用対象者のproposed−controlで計算する。仮説4の主指標は参加者ごとの率の平均で、用語件数比は参考値。各用語は回次内に一度だけ数え、事前との分類一致を参照する。旧recurrence_flagの総件数比を使わず、値は0〜1に収まる。

後半回次は受験者が異なる参考値であり、全回を合算して主指標にしない。現行経路の回次はretest_1/retest_2のみで、旧版の多数回受験は旧保存値として保全する。

## アンケートの目標

仕様版37では事前アンケート`presurvey-baseline-v2`と事後アンケート`posttest-10point-v3`を別phaseで保存する。仕様版36の`presurvey-baseline-v1`（Boolean形式）および旧posttest v1/v2の保存済み回答・旧5段階列は変換・補完しない。仮説5の教材評価6評定はposttest phaseだけから読み出す。6仮説の式・比較回次は変更しない。

- 事前知識6項目：事前学習、ファインチューニング、RAG、プロンプトエンジニアリング、マルチエージェント、記憶プロセス。仕様版37では「知らない／聞いたことがある／意味を知っている／説明できる」の4択で回答する。`prior_term_knowledge`には順に`unknown`／`heard_of`／`knows_meaning`／`can_explain`を保存し、全項目必須。仕様版36の回答は`presurvey-baseline-v1`のBooleanのまま保全し、尺度変換しない。記憶プロセスには「AIが以前の会話で伝えた利用者の希望を記憶し、次回以降の回答に利用する仕組み」と付記する。
- 事前の一般2項目：普段のAI利用頻度、AIを使いこなせているかの自己評価。各1〜10の整数で必須。
- 事後のシステム評価2項目：操作しやすさ、システムのわかりやすさ。各1〜10の整数で必須。
- 事後の教材6項目：内容のわかりやすさ、読みやすさ、日本語のわかりやすさ、難易度の適切さ、学習への役立ち度、量の適切さ。表示者は全項目必須、未表示者は自動で対象外としnull。
- 事後の自由記述：任意。省略・null・空文字・空白のみを受け付け、文字列は前後空白を除去して保存する。

評価は肯定文への同意度（1：全くそう思わない〜10：非常にそう思う）。利用頻度は1：使用しない〜10：非常に頻繁に使用する、AI活用の自己評価は1：全く使いこなせていない〜10：非常によく使いこなせている。v2はself_rated_ai_proficiencyへ保存し、v1のself_rated_ai_knowledgeと意味を混同しない。難易度・量の高得点は「易しい・多い」ではなく「適切」であることを意味する。

教材評価は主観評価であり、因果機序や学習理解の証明ではない。

## 保存・管理・CSV

EvaluationSummary.hypothesis_metrics_jsonに参加者指標と分子・分母・観測状態・用語/セッション別・回次別の根拠を保存する。アンケート・教材表示の追加も評価キャッシュの更新対象にする。

指標版が異なるキャッシュは、現行プロトコルで事前テスト採点済みの参加者に限って評価サマリーを新規作成する。過去のサマリーを上書きせず、旧プロトコルの閲覧・出力では再計算しない。

管理画面の「6仮説の記述集計」と次の専用CSV・Excelブックを同じ計算関数から生成する。各Excelブックは対応するCSVと同じ列・行を持つ1シート構成で、数値列はExcelの数値として、文章・JSON列は文字列として保存する。

- /api/admin/export/hypothesis_metrics.csv：参加者別の長形式。
- /api/admin/export/hypothesis_group_summary.csv：群別、群間差、回次・経路等の詳細。
- 上記CSVに対応する`.xlsx`：`hypothesis_metrics.xlsx`と`hypothesis_group_summary.xlsx`。
- 統合ログCSV・Excel：全体ログと被験者ログを別ファイルで出力する。仕様版43で`test_content_mode`列を追加し、それ以外の従来列とvalue_json、旧値は維持する。
- 既存のExcel互換CSVはUTF-8 BOM付きCSVであり、`.xlsx`ブックとは別形式。

仮説2の到達者だけの平均は条件付き集計である。未達者の値はnullとし、群のmissing_count/censored_countに人数を計上する。ここで未観測なのは満点までの総回数であり、表示済みセッションの記録欠落を意味しない。未達人数と観測回数・終了状況を併記し、この平均だけで学習効率が改善したと断定しない。

未達者はh2.censoring_reasonで「途中中断（give_up）」「継続中（in_progress）」「完了・満点未達（completed_without_mastery）」「終了状況不明（other）」に分ける。明示的な終了理由がなく未終了の場合だけ継続中とし、無操作時間から中断を推測しない。群のh2.censoring_breakdownには各内訳の人数と観測セッション数の平均・中央値を保存し、管理画面と専用CSVのdetails_jsonへ同じ内容を出す。未達者全体のobserved_nonattainer_sessionsも維持する。到達済みならその後の終了理由によらずcensoring_reasonはnullとする。仮説6の登録者母数・満点到達判定は変更しない。
